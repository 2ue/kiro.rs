# 01 · 页面架构建议

> 定方向册。回答"dashboard 该怎么组织"。

---

## 核心判断：把总览拆成"健康层 + 分析层"双层

当前 `features/overview/overview-page.tsx`（1000+ 行）把"实时健康监控"和"历史趋势分析"塞在同一页。这两者对应运维的两种割裂心智：

| 心智 | 关注问题 | 时效 | 看的频率 |
|---|---|---|---|
| **健康监控** | 系统现在健不健康？有没有要我立刻处理的？ | 秒级 | 每天第一眼、出事时盯着 |
| **历史分析** | 过去发生了什么？钱花哪了？容量够不够？ | 分钟/天级 | 排查、复盘、规划时 |

混在一页的后果：健康信息被趋势图淹没（出事时找不到重点），分析能力又因为要兼顾"轻量总览"而做不深。

## 建议的导航结构

落在现有"分析域"下，拆成两个页面：

```
分析域 Analytics
├─ 总览 Overview     → 重定位为「实时健康 + 待办」（健康层）
│                       秒级关注，短轮询，一眼定生死
└─ 分析 Analytics    → 历史趋势、成本、维度下钻（分析层）
                        排查/复盘，长轮询或手动刷新
```

- **总览页**（健康层）模块明细见 [02-overview-health.md](./02-overview-health.md)
- **分析页**（历史层）模块明细见 [03-analytics.md](./03-analytics.md)

## 为什么不推荐"继续单页堆模块"

- 单页已 1000+ 行，继续加存储健康、外部池实时态、成本分析只会更难维护。
- 健康层要短轮询（10-15s），分析层不该被高频轮询（浪费请求、历史数据不变）。同页无法分层设置刷新策略。
- 拆页后健康层可以做到"首屏不滚动看全"，这是运维监控页的基本要求。

## 迁移策略（降低返工）

不必一次性重写。建议：

1. **先在现有总览页内做加法**：补健康总评条、存储健康卡、外部池实时态（见 02），验证数据接入与视觉。
2. **再拆分**：把趋势、维度排行、外部池盈亏等"分析向"模块迁到新建的分析页（见 03），总览页只留健康向模块。
3. 拆分时复用现有的 `PageContainer`/`SectionCard`/`StatCard`/charts，不引入新依赖。

## 与现有路由的衔接

现有路由（`ui/src/app/router.tsx`）已是懒加载结构，新增分析页只需：
- `ui/src/types/ui.ts` 的 `navPages` 加一项（domain: 'analytics'）；
- `router.tsx` 加一条懒加载路由；
- 新建 `features/analytics/analytics-page.tsx`。

不改动 auth、shell、其余路由。
