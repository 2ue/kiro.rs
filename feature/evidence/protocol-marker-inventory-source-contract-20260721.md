## Locked Source Contracts

The new contract file is:

- [`../tests/protocol-marker-inventory-source-contract.test.mjs`](../tests/protocol-marker-inventory-source-contract.test.mjs)

It verifies the following production-source invariants after excluding Rust test modules and `*/tests.rs` fixtures:

1. Internal transcript role markers are confined to the sanitizer:
   - `user Continue` appears only in `src/anthropic/transcript_sanitizer.rs`;
   - `user Tool results provided` appears only in `src/anthropic/transcript_sanitizer.rs`.

2. `Tool results:` appears only in:
   - `src/anthropic/transcript_sanitizer.rs` as a legacy scaffold signature;
   - `src/anthropic/stream.rs` as a bounded observability marker.

3. `<function_results>` and `</function_results>` appear only in `src/anthropic/stream.rs` as observability markers. No production path is allowed to build a new user-visible function-results transcript.

4. `<function_calls>` and `</function_calls>` appear only in `src/anthropic/stream.rs`, where they are part of the strict literal-tool-call recovery parser.

5. Bare `<invoke` and `</invoke>` do not appear as production code literals after comments and tests are removed. This prevents a future production path from parsing arbitrary bare invoke text.

6. `[previous output]`, `[trimmed output]`, and `[duplicate output]` do not appear in production source. These placeholders therefore cannot be generated by current production Rust code.

7. Current and historical tool-result-only user-message placeholders are the inert dot `"."`, not `Tool results provided` or `Tool results:`.

8. Empty tool-result content normalization uses the neutral text `Tool result content was empty.` and does not synthesize transcript scaffolding.

9. Invalid duplicate/orphan tool-result repair drops or deduplicates structured results without copying rejected result content into ordinary user text.

10. Legacy `textified*` / `flattened_history_tool_uses` counters remain diagnostic fields; production code does not increment them as a content textification action.

11. Literal function-call recovery remains scoped to complete `<function_calls>...</function_calls>` / namespaced envelopes, requires all tool names to be known, and checks protocol position before converting text back into `tool_use`.

## What This Proves

This closes a source-level gap in the previous protocol contamination evidence: the production codebase no longer relies on a single `Hashxxxxxxxx` fingerprint to prevent leakage. The broader marker family is either:

It also proves the old “tool result textified into prose” class is not active in production repair paths: rejected structured tool results are dropped/deduped, not copied into assistant/user text.
