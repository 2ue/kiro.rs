## 构建产物生命周期

- 所有本地 `cargo fmt/check/test/build` 都通过 `feature/tests/run-cargo-scoped.sh <scope> -- <command...>` 执行。只有明确记录“整个文件系统在 job 后销毁”的 CI 可豁免；长期 runner、开发机和共享 CI workspace 不豁免。
- wrapper 在 Git common dir 中原子登记 reservation：默认每批预留 12 GiB，并保留 20 GiB 空闲下限。并发支线只有在 `free - floor - active reservations >= requested` 时才准入；并发本身允许且不是本次事故根因。
- 每条支线拥有唯一 scoped target，强制 `CARGO_INCREMENTAL=0`，并在该逻辑批次成功、失败或收到 INT/TERM/HUP 后立即删除 target 和 reservation。不能等所有支线结束后再统一清理。
- 不可捕获终止留下的 owner 由下一批或 `--reap-stale` 根据 wrapper PID/start、reservation ID 和 command PID/start/PGID 回收。wrapper 被 SIGKILL 但命令进程组仍活时必须保留 target/reservation；完整进程组退出后才回收。活 owner、身份不确定、marker 不完整或删除失败时 fail closed，绝不删除未知目录。
- cleanup 一旦开始便移除 EXIT trap 并忽略后续 INT/TERM/HUP，避免第二次普通信号打断 target/reservation 删除；SIGKILL 仍由上述 stale 协议兜底。
- 多轮测试放在同一个逻辑构建批次中；若后续运行时测试需要 binary，必须在 wrapper 退出前只复制最终 binary 到独立目录并记录 SHA-256。所有 runner 显式接收绝对、冻结的 `KIRO_RS_BINARY`，不能查找 `target/debug`/`target/release`，也不能静默重建。
- 原始大报告写入有 owner 的临时目录，提交前只保留 `feature/evidence/` 下的脱敏摘要和哈希；`deps/build/incremental` 不能作为证据保留。
- 发布前执行 `node feature/tests/inventory-build-artifacts.mjs --gate`。repo/default、登记 worktree、reservation、显式环境和 bounded private-temp target 都会盘点；未知/unmanaged target、活跃或 stale reservation、target 引用进程、扫描截断或进程检查不完整均阻断发布。inventory 完全只读，Docker 只报告 `system df`/人工清理提示。
- 每个 handoff 记录 build target 清理前大小、`removed=true`、`reservation_released=true`、路径不存在及清理后可用空间。最终 gate 还要确认 inventory 为 pass。

典型构建与冻结候选：

```bash
candidate_root="$(mktemp -d "${TMPDIR:-/tmp}/kiro-candidate.XXXXXX")"
artifact_root="$(mktemp -d "${TMPDIR:-/tmp}/kiro-validation-artifacts.XXXXXX")"
cleanup_validation_roots() {
  rc=$?
  trap - EXIT INT TERM HUP
  rm -rf -- "$candidate_root" "$artifact_root"
  exit "$rc"
}
trap cleanup_validation_roots EXIT INT TERM HUP
KIRO_FROZEN_BINARY="$candidate_root/kiro-rs" \
  feature/tests/run-cargo-scoped.sh release-candidate -- \
  bash -lc 'cargo +1.92.0 test && cargo +1.92.0 build --release && install -m 755 "$CARGO_TARGET_DIR/release/kiro-rs" "$KIRO_FROZEN_BINARY"'
shasum -a 256 "$candidate_root/kiro-rs"
KIRO_RS_BINARY="$candidate_root/kiro-rs" \
  KIRO_VALIDATION_ARTIFACT_DIR="$artifact_root" \
  node feature/tests/<runtime-runner>.mjs
node feature/tests/inventory-build-artifacts.mjs --gate
```
