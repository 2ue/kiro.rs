# 提示词注入改造：逐项开关，由路由显式关联

日期：2026-10-23　基线：main `65661db`（0.0.210）　分支：`feat/prompt-injection-routes`（worktree `../2ue_kiro.rs-prompt-inject`）

## 目标

1. 代理写进上游请求的每一段提示词都有自己的开关，开关之间互不影响。只有内容上确实相互依附，或者属于某个功能的项才有依赖关系。
2. 注入项本身不带路由规则。路由在策略页上显式设置"跟随默认 / 开 / 关"。路由配置分成"缓存 / 提示词注入 / 功能"三个分区。
3. 页面展示每一项实际注入的文本、关闭后的影响和建议。能编辑的文本可以编辑，并提供预览，预览走真实的转换代码。
4. 和提示词开关绑在一起、但本身不是提示词的功能拆出去，单独控制。
5. 旧配置升级后行为等价；有意改变的地方逐条列出。
6. 仓库里描述旧机制的文档删除或改写，只保留最终结果。

## 已定的取舍

- `/cc` 原来的默认规则迁移为 `/cc` 路由上的显式设置，新装默认值是关（任务质量这一项在 `/cc` 上显式开）。
- 分块写入策略（A7）只在请求声明了 Write/Edit 工具时注入。
- 身份输出过滤的正则这次不改，只记录（05 第 4、5 条）。
- 协议控制标签（thinking、tool_choice）只读，只能开关。
- 外部池开关只对能用于外部池的 4 项提供（A1、A2、A4、A5），可以按路由覆盖。
- 删除提示词总开关、各注入项的路由规则，以及 `bodyConversion` 里的两个重复开关；页面提供"全部设为关"的批量操作。
- 运行配置页和旧版 admin-ui 不再编辑提示词，统一在新页面编辑。
