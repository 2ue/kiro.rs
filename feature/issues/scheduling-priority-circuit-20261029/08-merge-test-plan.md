# 合并测试计划（test/merge-sched-round2）

分支 `test/merge-sched-round2` = 远端 main `12e2db68` + `feat/zyphrzero-adoption-round2`（`fd0f68a7`）+ `fix/scheduler-smooth-dispatch`。

约束：

- 远端账号只做 opus 相关的少量验证，不压测、不大量消耗；代理、并发、RPM 与现网一致。
- 本地 JSON 账号只能用 haiku-4.5、sonnet-4.5，先探测额度和模型。
- 压测、异常注入一律用本地 mock Kiro 上游和 mock 外部池。
- 每轮结束清理进程、临时库、Redis db、临时目录。

## 1. 单元与集成（全量）

- CI 同一脚本，带 PgSQL、Redis 集成测试，`--all-targets`。
- clippy 基线、check-diff、前端两套类型检查、前后端契约脚本。

## 2. 调度场景（mock Kiro 上游 + mock 外部池）

账号：优先级 0 三个、优先级 10 两个，每号并发 3；排队上限 20、最长等待 60 秒；熔断默认关闭。

| 场景 | 期望 |
| --- | --- |
| 正常负载 | 全部成功，只用优先级 0 |
| 小并发突然大并发 | 首选档满后同一次选号降档；超出容量的请求快速 429 且 Retry-After 合理；负载回落后立即恢复 |
| 持续大并发（上游变慢） | 槽位一直跑满；排队持续推进；`/readyz` 不报停摆；停止后几秒内排空 |
| 大并发 + 30% 上游 500，随后恢复 | 错误在内部换号消化，对外成功率接近 100%；恢复后全部成功 |
| 大并发 + 上游短暂全挂（4 秒），随后恢复 | 只有挂掉期间的部分请求失败；恢复后立即成功，不出现长时间冷却或熔断 |
| 大并发 + 上游持续 429（30 秒），随后恢复 | 期间快速返回、不堆积；恢复后几秒内恢复正常 |
| 单个账号持续 500 | 请求换到其他账号，对外几乎无报错；该账号连续故障后被冷却 |
| 两个账号被风控（403） | 只禁用这两个账号，其余照常；熔断默认关闭不触发 |
| 连接被重置（20%） | 换号重试消化 |
| 大并发长流（60 段 × 100 毫秒） | 全部完整结束；排队与超时正常 |
| 本地满时转外部池；外部池故障与恢复 | 本地满或本地失败转外部池；外部池故障时换池或回本地；恢复后正常 |
| kill -9 / SIGTERM | 约 30 秒内回收租约 / 退出即释放 |
