## 端到端验收（mock 上游，2026-10-30）

环境：release 构建；本地隔离 PgSQL 库和 Redis db；5 个 mock 账号，优先级 0 三个、优先级 10 两个，每号并发 3；排队上限 20，最长等待 60 秒。客户端用 `scripts/loadtest/kiro-load-runner.mjs`，每个请求一个新会话。

| 场景 | 结果 |
| --- | --- |
| 正常负载：上游 0.3 秒，6 并发，15 秒 | 272/272 成功；全部落在优先级 0，三个账号各 90 个；调度等待最长 46 毫秒；优先级 10 没有流量 |
| 过载：上游响应头 3 秒，40 并发，20 秒 | 125 个成功，即 15 个槽位按 3 秒一轮跑满；其余 19611 个返回 429，p50 1.8 毫秒，其中 19491 个在解析请求体之前拒绝；Retry-After 为 2–3 秒，按排队长度和拿号速率算出 |
| 负载停止 | 几秒内排队归零；`/readyz` 200，`dispatchProgressing=true` |
| 恢复后 6 并发 10 秒 | 163/163 成功 |
| 持有 9 个租约时 `kill -9`，新实例启动 | 新实例启动后 26 秒内全部回收，之后 181/181 成功 |
| 持有 6 个租约时 SIGTERM | 2 秒内租约归零，日志 `已释放本实例 Redis 并发租约 released=6` |

## 模型目录（02 的待查项）

现网 497 个凭据都没有 `supportedModels`，目录优先在现网从不生效，不是账号空闲的原因。发现流程只对 API Key 凭据运行；OAuth 凭据目录为空表示不限制模型。目录优先只在有目录的账号可调度时把空目录账号排到后面，有目录的账号满了以后空目录账号照常接流量。
