# 待决策项、实施顺序、验收

## 待决策

1. Fast 是否继续排在优先级前面。建议保留。
2. `balanced` 现在其实按档调度。建议这次不动，只把现状写进说明。
3. 首选档满时立刻降档还是先短暂排队。建议立刻降档。
4. 同会话在单账号的最大并发要不要从 3 调小。建议默认不变，开放成配置项。
5. 会话迁回高档时上游真实成本会多一次冷启动，是否接受。
6. 租约回收和排队、超时相关的修改见 [04-incident-2002-queue-lease.md](04-incident-2002-queue-lease.md)。

## 实施顺序

1. 现网只读数据确认账号分散的原因排序（见 02）。
2. 调度纯重构 + 场景矩阵基准测试。
3. 优先级规则、同档分散、会话迁移，各自单独提交。
4. 熔断改造（03）。
5. 租约回收与排队（04）。
6. mock 上游 + 真实 `claude -p` 调度测试；全量测试按 CI 并发跑（需要磁盘空间）。

## 验收

- 优先级 0 有空闲时，新会话 100% 落在优先级 0；预热中的低档账号不越档。
- 优先级 0 全满时，新请求在同一次选号内降到下一档，不排队。
- 绑定在低档的会话，在高档有空闲后按限速迁回；迁回前后对外 usage 的缓存字段连续（默认配置）。
- 同档内账号的绑定会话数差异收敛（具体阈值按现网数据定）。
- 新导入账号被风控，不触发全池熔断；曾经成功过的账号被风控达到比例阈值才打开；打开时清空窗口，有半开探测。
- 进程被强制杀掉后，残留的并发租约在约 30 秒内回收；正常停止时租约在退出前释放（见 04）。
- 排队打满时，拒绝在毫秒级返回，Retry-After 随排队长度变化；被拒请求和中途取消的请求都有用量记录；健康检查能发现调度停止推进（见 04）。
