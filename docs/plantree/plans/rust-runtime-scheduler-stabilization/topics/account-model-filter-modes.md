# 账号模型白名单与黑名单

Role: 本地账号、外部池账号与硬分叉账号模型筛选的实施契约

Status: In Progress / execute-ready

Date: 2026-11-23

Authority: 当前会话明确要求三个分支实现白名单/黑名单、批量设置、模型选项与一键填充。

Related: [Roadmap](../roadmap.md)、[Fable 协议校对](../../../../analysis/fable-protocol-compatibility-20261123.md)

## 行为

- 同一账号内白名单与黑名单互斥，一个模式解释同一份列表；不同账号可以使用不同模式。账号自身策略覆盖订阅等级策略，不将两级名单叠加。切换模式只更新草稿，保存后生效，界面明确名单含义。
- 保留 `supportedModels` 列表并新增强类型 `modelFilterMode: allowlist | denylist`，缺省 `allowlist`，旧配置及记录行为保持。
- 白名单：非空只允许列出模型；本地账号空列表继续继承订阅等级模型限制，外部账号空列表不限制。账号自身非空列表继续覆盖订阅等级。
- 黑名单：账号自身策略生效，只拒绝列出的模型；空列表允许任意模型，不继承订阅等级白名单。名单使用现有同版本模型名兼容规则，大小写归一，thinking/[1m] 兼容按原匹配实现。
- 无模型的辅助请求保持原行为。黑名单对请求/映射候选采用“任一命中即拒绝”，防止映射绕过限制。
- 黑名单不构成账号已支持/已发现模型的证据，不能进入“明确支持该模型优先”的逻辑，也不能把被禁止模型提升进模型目录。
- 容量、排队、会话粘性、重试、缓存、导入导出、复制、存储重载均使用同一策略；保存遗漏字段保留模式，旧格式缺省白名单。

## 设置入口

- 单个账号支持切换名单模式、逐个选择、手动输入、清空和一键填充。
- 选项以系统现有模型目录为主，合并已保存项，避免官方清单遗漏外部别名和自定义模型；单账号上游发现作为补充。黑名单下获取上游清单仅提供候选，不自动把全部可用模型变成禁用模型。
- 本地账号批量编辑新增模式/模型列表；外部池新增批量模型设置；claude-main 扩展现有批量账号编辑并保留已有追加/移除能力。
- 显示清楚本地空白名单继承与空黑名单不限制，纠正现有“空列表总是不限制”的提示。

## 分支、验证及发布

- main 同时覆盖本地账号与外部池；forced-main 合入同等能力并保留自身差异；claude-main 独立移植账号逻辑和 UI，不直接合并主线。
- 验证旧模式兼容、两模式空/非空、同版本别名、被禁止模型无法通过映射/满载/粘性/重试进入账号、CRUD/复制/重载/导入导出、批量及 UI 选择/填充。
- PostgreSQL/Redis 使用隔离验证资源；所有本地 Cargo 命令经现有 scoped wrapper，按分支清理构建产物。
- 完成三个分支相关及完整质量门后推送 GitHub 自动发布并核验镜像，生产部署不属于本轮授权范围。
- usage 整形、rawUsage/rawCostUsage、成本公式和账号分组保持原实现。


## 实现说明

- API 保留 `supportedModels`，通过 `modelFilterMode` 解释同一列表。模式只接受 `allowlist` 或 `denylist`；旧记录默认为白名单，编辑省略模式则保留当前值。
- 单账号编辑切换模式时保留草稿列表，并明确提示按新模式解释；保存前不生效。本地批量和外部池批量按选定模式整体替换。
- Claude 批量保留替换、追加、移除、清空。跨模式仅允许替换/清空；追加/移除遇到模式不同的账号会报该账号失败，避免反转原列表含义。
- `/supported-models/sync` 作为旧版“发现并保存支持目录”操作，明确写成白名单；黑名单编辑使用只读 discover 接口，补充候选后由操作者保存。Claude 黑名单不能执行“提升为模型目录”。
- 本地账号模式与列表同次持久化，CAS 合并以整组检查冲突。外部池在同次 SQL 更新中写入两字段，缓存失效与跨实例通知沿用现有机制。
- 外部池黑名单同时检查模型请求候选与池内映射目标，资格预判与实际选择共用同一实现。沿用原模型名兼容规则，不引入通配符匹配。

## 防止调度风暴的门禁

- 名单在模型资格层过滤；全部被排除视为无候选，不作为容量暂满反复等待，不进入上游重试或错误冷却。
- 模型变体按列表内容缓存，相同名单复用；线程缓存最多 128 组，名单变更按内容重新展开，模式反转独立于缓存，避免过期语义。
- 本地批量模型设置只在批次结束统一唤醒和发布一次模型配置通知，部分条目成功也会通知；外部/Claude 批量限制同时最多 4 个账号更新。
- 并发 1/16/64 的拒绝请求必须没有 Redis 容量调用；缓存已热时不得重复查询 PostgreSQL；更新后并发 64 请求共享一次配置加载。
- 以上检查只使用隔离数据库和模拟账号，保持既有容量、租约、队列超时及重试预算算法。
