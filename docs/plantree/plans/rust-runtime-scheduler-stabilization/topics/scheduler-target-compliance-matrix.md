## 状态定义

- `符合（focused）`：已有源码和隔离 focused 测试支持目标，但尚未经过持续流量或多实例门禁。
- `局部符合`：核心边界已存在，但仍有结构缺口、未覆盖的组合或可观测性不足。
- `不符合`：当前实现与目标语义直接冲突，或已确认缺少必要机制。
- `待测试`：源码方向没有足够证据，必须通过隔离持续调度验证。

## 当前结论

当前实现不是“完全不支持调度”，而是已经具备多个局部正确边界，但尚未满足统一目标：

1. **已经可以暂时守住的边界**：外部直连不回本地、local-first 的有条件 fallback、一次 bounded local rescue、同池/跨池有限重试、冷却清除。
2. **明确不符合目标的结构**：普通错误过早进入池级冷却、外部池静态优先级仍是硬门槛、多层等待没有共享总 deadline、调度诊断缺少完整候选和尝试账本；最终 usage 计算与调度域必须继续保持独立。
3. **不能仅凭源码宣布通过的部分**：连续故障波恢复、三池优先级溢出、双实例冷却竞态、旁路故障下的长时稳定性、长会话 sticky 逃逸。

因此当前阶段结论是：

> 核心目标已经确认，当前运行时代码不能按 132 的冷却语义继续发版；必须先按 [外部池高可用调度执行计划](external-pool-ha-scheduler-execution-plan-20260805.md) 修复“不符合”项，再跑持续调度验证。
