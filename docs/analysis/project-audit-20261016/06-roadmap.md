## 通用验收与发版规范

1. 每个编号单独提交，提交信息写明编号，例如 `fix(scheduler): type local scheduler errors for fallback decisions (R8)`。
2. 每个修复至少一个回归测试，并做过"去掉修复后必须失败"的反向验证。
3. 全量测试在空闲机器上串行运行，与上一个版本的结果逐条对比。不要和构建并行，否则时序测试会误报。
4. 涉及调度、Redis、PG 的改动，必须用真实账号在隔离环境实测：独立 PG 库、独立 Redis 容器、只用 haiku 4.5 / sonnet 4.5。
5. 发版沿用现有流程：快进合并到 main，`chore(release): x.y.z` 只改 `Cargo.toml` 和 `Cargo.lock`，推送 `vX.Y.Z` tag，盯 `Publish Docker Images` 到全绿，再到 GHCR 核对 manifest 包含 amd64/arm64。
6. 部署只重启 app 容器，部署后用 `usage_records` 对比部署前后各 2 小时的成功率与延迟，并检查 ERROR/WARN 分布。
