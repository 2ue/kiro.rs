# 空回的对外语义、重试节奏与账号摘除：实施方案（2026-11-05）

## 背景

现网 24 小时（两台合计）：

- 空回（上游 200 但整条流从头到尾没有文本、推理或工具调用）约 5.5 万次，占全部失败的 95% 以上。
- 流式空回对外状态码是 200（流里补 `error` 事件）；非流式是 502。
- 上游报 `COMPLETED` 却一个字没吐的非流式请求被当成成功，下游按 200 计费（6 小时 2 条）。
- 对外文案只有三句话，且都带 "contact the administrator"，调用方分不清是谁的问题、能不能重试。
- 流式失败 99% 发生在下游收到任何字节之前（中位 1.3~1.7 秒，P99 13~18 秒），正常请求首个输出中位 5.5~7.5 秒、P90 20~29 秒。

## 目标

1. 只要是空回，对外不返回 200（流式在首输出前失败直接 5xx）。
2. 不误伤正常长流：空回只在上游流结束时按整条流判定，过程中出现空帧、只有心跳、思考很久，都不算空回。
3. 对外提示语按原因分类，说清楚「发生了什么、谁的问题、要不要重试」，不再出现 administrator。
4. 空回重试的节奏可配置：不间隔 / 固定间隔 / 指数递增，带抖动。
5. 空回导致的账号摘除有独立总开关，可以选择不摘除。
6. 附一份对外错误说明文档。

## 设计

### 1. 空回判定（不改语义，只堵漏洞）

- 判定时机不变：只在上游流 EOF 时执行一次。
- 判定标志是累积的：整条流里出现过一次非空文本 / 推理 / 工具调用即视为有输出。
- 唯一改动：上游报 `COMPLETED` 但整条流无输出，也判空回（流式 `upstream_terminal_failure_detail`、非流式 `missing_explicit_status` 分支前移）。内容过滤拒答仍视为正常回答。

### 2. 流式首输出前压住 HTTP 响应头

- `create_sse_stream` 生成的字节流不变；在其外面加一层「首包等待」：先拉取字节流的第一个 item。
  - 第一个 item 是正常 SSE 字节（`message_start`/内容/保活）→ 回 200 + 该 item + 后续流。
  - 字节流结束前一个字节都没有、且记录的终止原因是失败 → 回 5xx JSON 错误（不发 200）。
- 预提交窗口内 `create_sse_stream` 本来就不产生字节，所以压住响应头不改变正常请求拿到第一个字节的时间；窗口到期（`streamPreOutputHold`，现网 15 秒）后它会发 `message_start` + 保活，此时才回 200。
- 为了让外层拿到「失败但没有字节」的信号，预提交失败时 `create_sse_stream` 不再在流里补 `error` 事件，而是把公开错误放进共享槽，由外层构造 JSON 错误响应。已提交（窗口到期后才失败）的仍走 200 + `error` 事件。
- 外部池兜底：预提交阶段失败转外部池时，外部返回成功则照常透传；返回错误则同样走 5xx JSON。

### 3. 对外错误分类

公开文案集中到 `envelope` 的一张表，每类有固定的状态码、`type`、中文 + 英文文案。错误 ID 作为排查编号附在末尾：`（请求编号：req_xxx）`，不再写 administrator。

| 类别 | 状态码 | type | 是否自动重试 |
|---|---|---|---|
| 上游这次没有返回内容（空回，已换号重试仍失败） | 可配置，默认 502 | 随状态码：502→api_error，503→api_error，529→overloaded_error | 取决于状态码 |
| 与上游连接中断 / 读取失败 / 超时 | 529 | overloaded_error | 是 |
| 上游模型繁忙 / 容量不足 | 529 | overloaded_error | 是 |
| 暂无可用账号 / 限流 | 429 | rate_limit_error | 是 |
| 输入超长 | 400 | invalid_request_error | 否 |
| 图片过大 / 过多 / 格式不支持 | 400 | invalid_request_error | 否 |
| 上游拒收请求格式 | 400 | invalid_request_error | 否 |
| 参数不被模型支持（上游原文） | 400 | invalid_request_error | 否 |
| 联网搜索失败 | 502 | api_error | 否 |
| 其它未分类内部错误 | 502 | api_error | 否 |

空回状态码由 `emptyTurnErrorStatusCode` 控制（可选 502 / 503 / 529，默认 502）：sub2api 过去 7 天从 59137 收到 3.7 万次 502、0 次 529，常见的 sub2api 收到 529 会把账号标成过载、暂停调度，所以默认不改现有行为，留给运维对比测试。流式在首输出前失败时同样使用该状态码；已经提交 200 之后才失败的，流内 `error` 事件保持 `overloaded_error`（让 Claude Code 自动重试），文案区分「中途中断」与「没有内容」。

### 4. 空回重试节奏

新增配置（运行时可改，两个前端同步）：

| 配置 | 默认 | 范围 |
|---|---|---|
| `emptyTurnRetryBackoffMode` | `none` | `none` / `fixed` / `exponential` |
| `emptyTurnRetryBaseDelayMs` | 100 | 0~10000 |
| `emptyTurnRetryMaxDelayMs` | 2000 | 0~30000 |
| `emptyTurnRetryJitterPercent` | 20 | 0~100 |

- 只作用于空回触发的换号重试；其它首输出前重试（读流失败、状态错误）不受影响。
- 延迟发生在释放原账号并发之后、选下一个账号之前，等待期间不占账号。
- 流式：延迟不超过预提交窗口剩余时间；窗口不够时不再等待和重试，直接以失败结束（5xx）。非流式：受请求级发送上限约束。
- 默认 `none`，与现有行为一致。

### 5. 空回摘除总开关

- 沿用 `credentialDegradeEnabled`，语义明确为「空回 / 流截断是否让账号暂时退出调度」；关闭后不计分、不摘除。
- 两个前端里把它和空回重试节奏放在同一组。

### 6. 对外文档

`docs/errors.md`：每类错误的状态码、type、中英文文案、常见原因、调用方该怎么做。不含服务器、账号等内部信息。

## 自检

| 问题 | 结论 |
|---|---|
| 压住响应头会不会让正常请求变慢 | 不会。预提交窗口内本来就不写字节，首字节时间不变；只是响应头和首字节一起发出 |
| 会不会把长流误判成空回 | 不会。判定只在 EOF 执行一次、标志累积；测试覆盖空帧、长时间心跳、慢出字 |
| 已经输出过内容后失败怎么办 | 协议限制，保留 200 + error 事件；这类请求下游确实收到了内容 |
| 改状态码会不会影响 sub2api 调度 | 空回状态码可配置、默认保持 502；其它类别保持原有状态码，只改文案 |
| 重试间隔会不会造成排队或拖超时 | 等待时不占账号并发；流式受预提交窗口约束，非流式受请求发送上限约束；默认不间隔 |
| 摘除总开关关闭后是否完全回退 | 是，不计分、不摘除，已有测试覆盖 |
| 文案改动会不会破坏客户端解析 | 只改 `message` 文本；`type` 与状态码只在空回类按配置变化，其它保持 |

## 风险与验证

- **压住响应头导致客户端超时**：只在预提交窗口内压，窗口本来就不发字节，正常请求拿到首字节的时间不变。用 mock 上游模拟 30 秒才出字的慢请求，验证 15 秒时收到 200 + 保活。
- **误伤长流**：测试覆盖「中间空帧后出字」「只有心跳很久后出字」「先出字后上游结束无 COMPLETED」，都必须是 200 正常完成。
- **外部池兜底路径**：测试预提交失败转外部成功（200 透传）和外部失败（5xx）。
- **计费**：失败一律 5xx 或带 error 事件，usage 记失败，不计费。
- 全量测试两种 features + 存储集成测试，合并最新 main 后发版。
