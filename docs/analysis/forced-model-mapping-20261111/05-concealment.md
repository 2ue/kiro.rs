# 05 不暴露真实模型

## 2. 身份与自述

### 问题

- Claude Code 的系统提示里本身就写了 "You are powered by the model named Opus 5.5 … exact model ID is claude-opus-5-5"。4.5 遵循系统提示，大多数情况下会按外显模型自称。
- 没有系统提示的 API 调用（直接问"你是什么模型"）时，4.5 会回答 "Claude Sonnet 4.5"，知识截止日期也会说 4.5 的。
- 现有身份提示（`catalog.rs:67`）只写 "You are Claude"，不带型号。而且**身份提示、轮次提醒、渠道泄漏过滤默认全部关闭**（`prompt_injection/mod.rs:96`、`:658`）。
- 代码里没有任何地方注入日期或知识截止。

### 方案

**默认开启：** 强制模式的路由默认打开身份提示、轮次提醒和输出侧过滤（含流式），并且在路由覆盖里不允许单独关掉。否则只要漏配一项，就会直接暴露。

**提示词侧：**

- 强制模式下，在身份提示里加入外显模型名。例如："You are Claude Opus 5.5 (model ID claude-opus-5-5), made by Anthropic."
- 注入位置沿用现有身份配置：system 首块，以及**只在有用户文字的轮次**加的提醒。这些注入要做到无感知（参见注入必须无感知的约定）。
- 客户端系统提示已经声明了型号时，不重复注入，避免冲突。

**输出侧（改写，而不是删除）：**

- 在 `identity_guard.rs` 现有的句级检查框架里，新增一类"模型自述"规则。
- 匹配到 "I am / I'm / 我是 … Claude (Sonnet|Haiku) 4.5"、"claude-(sonnet|haiku)-4[-.]5" 这类**自述句**时，把型号部分改写成外显模型名，而不是整句删除。删句会让回答缺一段，反而显得可疑。
- 只匹配自述，不匹配用户代码、文档或对模型列表的正常讨论（沿用现有的"第一人称 + 型号"约束）。
- 可见的 thinking 也要过同一套检查。

**知识截止：** 由 07 篇的知识库处理。

- K0 卡片会声明外显模型的知识截止，并配上"更晚的事情可能不知道"这句兜底。
- K1/K2 补上收录范围内的事实。
- 只声明截止日期、却不补充事实，模型会编造答案，所以两者必须同时上线。
- 没收录的近期事件仍然是残留指纹（见第 3 节）。

**验证：**

- 改动提示词文案时，需要用对照组证明约束仍然有效（参见注入文案要验证遵从率的约定）。
- 测试矩阵：带/不带 Claude Code 系统提示 × 中/英文 × 直接问型号、问知识截止、问"你和 4.5 有什么区别"。

## 3. 无法消除的残留指纹

下面这些能被有心的调用方察觉，协议层无法消除：

| 指纹 | 说明 |
|---|---|
| 响应速度 | Haiku 4.5 的输出速度明显比 Opus 快 |
| token 计数比例 | tokenizer 不同；可以按系数放大来掩盖，但不精确 |
| 能力水平 | 复杂推理、长任务、编码质量的差距 |
| 知识截止 | 知识库收录范围以外的近期事件仍答不上来；补得越全，这个指纹越弱 |
| thinking 风格 | 提示词思考和原生 adaptive 思考的节奏不同 |
| 上下文表现 | 长会话后期会遗忘早期内容（04 的退避造成） |

这些内容需要在第 06 篇的风险说明里如实告知，作为是否上线的决策依据。
