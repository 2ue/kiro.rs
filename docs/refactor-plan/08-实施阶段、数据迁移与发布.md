# 实施阶段、数据迁移与发布

## 阶段 0：行为冻结和准备

建立当前版本的 characterization suite：请求路径矩阵、local/external route、fallback、Kiro converter、external raw passthrough、SSE、usage、cache golden cases。导出一份脱敏配置 fixture，记录 PostgreSQL schema、Redis key 前缀、默认值和运行版本。此阶段不改生产热路径。

完成以下准备后才能进入 Go 实现：

- 按已确定的 Go 后端、React + TypeScript + Tailwind CSS 前端分层，锁定 Go、Node、pnpm、React、Tailwind、数据库客户端和 Redis 的具体版本矩阵，并提交 lockfile、checksum 和镜像 digest。
- 生成 OpenAPI v2 schema 和旧 API 映射表。
- 选定双 Redis 故障域、secret encryption/key rotation 方案。

## 阶段 1：Go 骨架与兼容读路径

实现 HTTP transport、provider registry、domain contracts、PostgreSQL/Redis repositories、Admin v2 read API 和旧配置读取器。Go 服务可以只读当前 Rust 写入的数据，不承担流量切换。对旧 `credentials` 和 `external_pools` 做 shadow projection，检查 channel/account 数量、字段哈希和 secret fingerprint 一致。

## 阶段 2：共享调度和 Provider 单元实现

先实现 generic scheduler、route policy、lease、attempt budget 和 typed error，再接入：

1. Claude Code upstream Provider：最小 passthrough/stream/usage 端到端。
2. Kiro Provider：逐步迁移 converter、endpoint、token manager 和 quota adapter。

每个 Provider 都有独立 contract tests；共享 kernel 不接受 provider-specific import。此阶段支持 shadow decision：Go 只计算 route/target，不发送上游，与 Rust decision 做 diff。

## 阶段 3：缓存模块迁移

把 Rust cache tracker/profile/calculator 的测试先转成跨语言 golden fixtures，再实现 Go cache domain。对同一个 request fixture 同时运行 Rust 和 Go，比较：resolved policy、conversation id、fingerprint、raw/shaped/reported usage、tracker update decision。差异必须归因并签收，不能用“近似相等”隐藏语义变化。

## 阶段 4：双写配置和数据迁移

- 新表与旧表并存；Admin v2 写新 schema，同时由兼容 writer 更新旧 `runtime_config` 视图。
- 所有 migration 有 `up`、`verify`、`down/rollback` 或明确不可逆原因。
- 旧 Kiro credential 与 external pool 导入新 channel/account 时保存 `legacySource`、旧 id、导入 revision 和 checksum。
- 迁移期间禁止复制 Redis in-flight lease、cooldown、sticky、quality state；这些是运行态，应在切换时冷启动或按明确的兼容读取策略恢复。

## 阶段 5：灰度切换

按路径/请求 API key/channel 白名单灰度。优先灰度 `/na` no-cache 和外部直连，再灰度 local-first/fallback，最后灰度 Kiro converter 和 high-cache。每次扩大范围前观察：成功率、首 token 延迟、SSE 终止、fallback 比例、reported usage 差异、Redis/DB 延迟、goroutine/memory/FD。

如果 Go 新路径发生协议、缓存或调度异常，feature flag 必须能在不改数据库的情况下回退 Rust；回退后新写入配置仍可被 Rust 兼容读取。

## 阶段 6：切换和清理

连续一个完整业务观察窗口通过验收后，将 Go 设为默认入口，保留 Rust rollback image 和旧 API adapter。再经过一个版本周期，才删除旧 external pool/credential 专用 UI；最后清理旧 Redis key 和兼容字段，且保留只读历史映射。

## 发布门禁

- Go `go test ./...`、race、静态检查、schema compatibility、migration verify。
- 前端 typecheck、lint、unit、component、Playwright E2E、visual regression、production build。
- Rust 旧实现继续跑完整 regression，直到兼容期结束。
- Docker 镜像包含固定版本、健康检查、优雅关闭、自动 migration 和回滚说明。
- 发布记录必须包含 schema version、config version、provider registry version、cache algorithm version 和 rollback target。
