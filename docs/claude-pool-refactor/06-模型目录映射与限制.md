# 06 模型目录、映射与限制

## 1. 模型目录

现状：`model_capabilities` 表的数据来自内置 seed `data/kiro-upstream-models.seed.json`、Kiro `ListAvailableModels` 后台同步（`main.rs:1038-1047`）、手工录入；`/v1/models` 由 `standard_anthropic_models()` 生成（`model_capabilities.rs:557`）；`claudeModelsOnly` 过滤列表。

新系统的目录来源：

| 来源 | 说明 |
|---|---|
| 内置 seed `data/anthropic-models.seed.json` | 当前 Anthropic 公开模型列表：id、display_name、context_window、max_output、min_cacheable_tokens、thinking 形式、价格。首次启动写入 PG，可"恢复内置值" |
| 手工录入 | 现有 `/model-capabilities/manual` 保留 |
| 账号发现 | 现有 `/external-pools/{id}/supported-models/discover` 读上游 `/v1/models`，结果只写入账号 `supportedModels`，**不自动进目录**；管理端提供"加入目录"操作 |
| 价格同步 | 现有 LiteLLM 源（`pricing.rs:10`）保留，手动触发 |

每个目录条目新增 `listed: bool`，替代 `claudeModelsOnly`：`/v1/models` 只返回 `listed=true` 的条目。seed 中非 Claude 条目默认 `listed=false`。

`/v1/models` 与 `/v1/models/{id}` 的响应格式不变（`model_capabilities.rs:1744-1798` 的规范化：别名、`-thinking`、`[1m]` 不列出，`claude-sonnet-thinking` 例外）。按路由取交集：只列出该路由 `modelRule` 允许、且至少一个该路由可用账号接受的模型（见 [10 Q7](10-待确认事项.md)）。

## 2. 模型解析与映射

三层，顺序固定：

```
请求模型
  │
  ├─ 1. 全局 modelMapping（modelResolutionMode: compatible / alias_only / exact_only）
  │     显式规则 > 精确匹配 > [1m]/-thinking 后缀 > 同版本写法 > 别名族 > 同族跨版本（可选）> 跨族（可选，默认关）> 透传
  │     位置：config.rs:4017-4146、model_capabilities.rs:1165-1335
  │     用途：得到"内部规范模型 id"，供目录查询（max_output、min_cacheable、价格）和 usage 记录的 model 字段
  │
  ├─ 2. 候选过滤：路由 modelRule ∩ 账号 supportedModels（用规范 id 和原始 id 都试一次）
  │
  └─ 3. 账号 modelMapping（passthrough / passthrough_mapping / direct_mapping）
        输入是原始请求模型，输出是发往该账号的 model 字段
        位置：external_pool/model_pipeline.rs、external_pool.rs:527-576
```

关键点：

- 第 1 层的结果**不写回请求体**。现有系统把 Kiro 解析后的 `upstream_model` 当作 `processed_mapping` 的输入导致过点号模型外发（见 `docs/model-routing-semantics/README.md`），新系统删除 `processed_mapping`，账号映射只看原始请求模型。
- 第 3 层只改顶层 `model` 一个字段（[02 第 3.1 节](02-目标架构与请求链路.md#31-请求体)）。
- 2026-11-23 移除 `normalizeModelVersionDots`：请求模型和上游 ID 不再自动互换点号/横杠。显式映射仍可填写任意渠道 ID；未命中按原有模式使用原请求或内部模型。
- 第 1 层对目录没有的模型按 `modelResolutionMode` 决定：`compatible` 透传、`exact_only` 拒绝（404）。

## 3. 模型限制

| 层 | 字段 | 语义 |
|---|---|---|
| 路由 | `modelRule: {mode: allow_all / allow_list / deny_list, rules: []}` | 新增。规则支持通配 `*` |
| 账号 | `modelFilterMode: allowlist / denylist` + `supportedModels: []` | 模式互斥，同一列表按当前模式解释；空列表不限制，缺省白名单保持旧行为 |
| 下游密钥 | 无 | C10：密钥只放准入与额度，不放模型限制 |

账号白名单仅允许列表内模型；黑名单仅禁止列表内模型。请求原名、规范候选或账号映射目标任一命中黑名单都会拒绝，防止通过别名绕过。保留日期、thinking、`[1m]` 和家族别名规则，不再展开点号版本，不增加通配符。路由自己的模型规则仍单独生效，账号允许的模型还须满足路由规则。

控制台的单账号编辑和快速编辑支持模式切换、系统模型下拉、单个选择、手动输入和一键填充；系统目录包含内置/同步及手工模型，账号发现用于补充候选。黑名单下获取上游模型不会自动加入禁止列表。黑名单不能提升为系统支持目录。

批量操作可替换、追加、移除、清空。切换白名单/黑名单必须使用替换或清空；追加/移除遇到账号模式不同会报该账号失败，原设置保留。编辑省略模式保留原值；旧导入缺省白名单，复制、导出和配置迁移保留模式。旧 `supported-models/sync` 的语义是发现并保存支持目录，明确切回白名单；黑名单编辑使用只读发现。

C8：不存在任何按名字或订阅等级写死的过滤。`subscriptionModelLists` 和 `claudeModelsOnly` 删除。

## 4. count_tokens

`POST /{route}/v1/messages/count_tokens` **本地估算**，不透传到账号上游（用户 2026-11-17 确认）。口径跟路由配置走：

- 先按该路由解析出的注入项（`routes[].promptInjection` 合并全局默认）把 system 注入写进请求，再估算；`promptInjection.applyToCountTokens=false` 时不计入注入。
- 该路由开启 `imageProcessing` 时先做图片物化/压缩再估算，与 messages 路径一致。
- 不占账号调度 lease，不消耗账号额度，账号池为空时同样可用。
- 删除 `countTokensApi*` 三个配置（见 [10 Q5](10-待确认事项.md)）。

本地 `token.rs` 估算保留，因为 usage 整形的基准输入依赖它（[05 第 3 节](05-usage整形与缓存策略.md#3-账号侧投影顺序) 第 2 步）。
