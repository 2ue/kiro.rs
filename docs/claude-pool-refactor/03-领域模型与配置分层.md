# 03 领域模型与配置分层

## 1. 实体一览

```
 Route ──(members)──▶ Account        每条路由选择它能使用的账号集合
   │                      │
   │ 挂载                  │ 覆盖
   ▼                      ▼
 缓存/usage 策略、注入、路由功能     账号级调度与传输参数
                       
 RequestApiKey  下游密钥：鉴权、准入、额度、允许的路由
 Model          模型目录：列表、能力、价格
 GlobalConfig   全局一份的默认值与基础设施
```

现有系统已经有这四个实体，只是名字和位置不同：外部池（`external_upstream_pools`）就是账号；路径前缀加 `pathOverrides` 就是路由；`requestApiKeyPolicies` 就是密钥；`model_capabilities` 加 `model_pricing` 就是模型目录。本章只做收口，不引入新概念。

## 2. 账号 Account

来源：`ExternalPool`（`external_pool.rs:578-643`），表 `external_upstream_pools`（`postgres.rs:13665`）。

### 2.1 保留字段

| 字段 | 说明 | 默认 |
|---|---|---|
| `id`、`revision`、`name`、`notes`、`createdAt`、`updatedAt` | 同现有 | |
| `baseUrl` | URL 拼接规则不变：末尾是 `/v1` 则追加 `/messages`，否则追加 `/v1/messages`（`external_pool.rs:11852-11884`） | 必填 |
| `apiKey` | 密钥。管理接口只返回掩码 | 必填 |
| `authType` | `bearer` / `x_api_key` | bearer |
| `headerProfile` | `generic` / `anthropic_passthrough` / `claude_code_mimic` | generic |
| `appendBetaQuery`、`headerOverrides`、`wireProfile`、`tlsProfile` | 同现有 | |
| `enabled` | 手动开关 | true |
| `priority` | 数值越小越优先 | 100 |
| `maxConcurrentRequests` | 单账号并发上限 | 10 |
| `supportedModels` | 模型白名单，空表示不限；匹配时继续展开点号/横杠、日期、`-thinking`、`[1m]` 变体（`external_pool.rs:12052-12290`） | [] |
| `modelMappingMode`、`modelMappingRequireMatch`、`modelMappingRules`、`normalizeModelVersionDots` | 同现有；`processed_mapping` 模式删除，因为它的输入是 Kiro 解析后的模型名 | passthrough_mapping |
| `routeMode`、`routeRules` | 账号自己允许的路由 | allow_all |
| `usageProjectionMode` | `pass_through` / `current_path_policy` | **current_path_policy**（见 2.3） |
| `streamResponseMode` | 继承全局 | None |
| `autoDisablePolicy` | inherit / disabled / enabled | inherit |
| `preOutputStreamRetryMode` | inherit / enabled / disabled / early_commit | inherit |
| `autoDisabled*` 五个运行态字段 | 同现有 | |

### 2.2 删除字段

| 字段 | 理由 |
|---|---|
| `requestBodyMode` | 只剩原字节透传一种（[02 第 3.1 节](02-目标架构与请求链路.md#31-请求体)） |
| `rawModelMode` | 顶层 model 改写由映射命中与否决定，不需要单独模式 |
| `preservePath` | 现有实现里从未生效（`external_pool.rs:11865` 忽略入口 path，只在 wire debug 输出） |

### 2.3 新增字段

| 字段 | 说明 | 默认 |
|---|---|---|
| `tags: Vec<String>` | 筛选与批量操作 | [] |
| `proxyUrl: Option<String>` | 出站代理，支持 http/https/socks5/socks5h；空时用全局默认代理，再空则直连。见 [10 Q6](10-待确认事项.md) | None |
| `costMultiplier: f64` | 账号真实成本相对官方价的倍率，只用于成本统计 | 1.0 |
| `overrides: AccountOverrides` | 账号级覆盖全局的调度与传输参数，见第 5.2 节 | 全部 unset |

`usageProjectionMode` 默认值从 `pass_through` 改为 `current_path_policy`：新系统 usage 整形是主功能（R4），且路由默认策略可以是 `no_cache`，由路由决定是否整形更符合 R7。保留 `pass_through` 作为账号级"强制不整形"的开关。导入旧配置时保留旧值。

## 3. 下游密钥 RequestApiKey

来源：`RequestApiKeyPolicy`（`config.rs:4873-4885`）。保留 `apiKey`、`name`、`enabled`、`requestAdmission`、`usageLimits`。

新增 `allowedRoutes: Vec<String>`（空表示全部）。按 C10，密钥层只放限制，不放行为配置。

## 4. 路由 Route

现状：路径前缀写死在 `router.rs:512-516`（`/v1`、`/na`、`/cc`、`/ha`、`/dfcache/{name}`），语义来自五张互相独立的 `pathOverrides` 表加 `definedCacheRoutes`。新系统把它们收口为一个路由定义列表，但**保留最长前缀匹配和这五个内置前缀**，以免现网客户端改地址。

```jsonc
"routes": [
  {
    "prefix": "/cc",                     // 路径前缀；根前缀 "/v1" 用 "" 表示
    "name": "Claude Code 高缓存",
    "enabled": true,
    "cachePolicy": { ... },              // 原 cachePolicy.pathOverrides["/cc"]，结构不变
    "reportedUsage": { ... },            // 原 reportedUsage.pathOverrides["/cc"]，结构不变
    "features": { ... },                 // 02 第 4 节的路由功能开关与参数
    "promptInjection": { ... },          // 原 promptInjection.pathOverrides["/cc"]
    "accountRule": { "mode": "allow_all", "rules": [] },  // 原 externalPoolRouteMode/Rules 的路由侧
    "modelRule": { "mode": "allow_all", "rules": [] }      // 新增：路由级模型白/黑名单
  }
]
```

- 内置路由 `""`（即 `/v1`）、`/cc`、`/ha` 默认 `current_high_cache`，`/na` 默认 `no_cache`，与现有 `with_builtin_path_defaults`（`config.rs:3550-3568`）一致；`/dfcache/{name}` 改为普通路由，前缀就是 `/dfcache/{name}`，不再需要 `definedCacheRoutes`。
- 现有 `reportedUsage` 对 `/cc`、`/ha` 的内置覆盖（`config.rs:1410-1434`）作为这两条内置路由的默认值保留。
- 账号与路由的双向规则保留：路由侧 `accountRule` 决定路由能用哪些账号，账号侧 `routeRules` 决定账号接受哪些路由，两边都放行才是候选（`external_pool.rs:6390`、`8116`）。
- 路由场景（`route_scenarios`）继续作为"所有路由与账号规则的命名快照"保留，去掉 local 部分。

迁移：启动时若 `runtime_config` 仍是旧结构（存在 `cachePolicy.pathOverrides`），由迁移函数拆成 `routes[]`。

## 5. 配置分层与合并规则

### 5.1 四层

```
defaults（代码内置） → global（runtime_config） → route（routes[]） → account（accounts.overrides）
```

密钥层不在这条链上，它只做限制（鉴权、准入、额度、允许路由）。

### 5.2 哪些字段在哪层

| 字段组 | global | route | account | 合并方式 |
|---|---|---|---|---|
| 基础设施（监听、PG、Redis、adminKey、下游密钥） | ✓ | | | 只有 global |
| 准入（RPM、并发、队列） | ✓ | | | 密钥可收紧 |
| 缓存策略、reportedUsage | 模板默认值 | ✓ 挂载 | `usageProjectionMode` 可关 | route 整体替换；account 只能关 |
| 提示词注入 | 默认开关与文案 | ✓ | | route 覆盖 |
| 路由功能 | 默认参数 | ✓ 开关 | | route 覆盖 |
| 模型目录、全局映射 | ✓ | `modelRule` | `supportedModels`、映射规则 | 限制取交集；映射 account 优先 |
| 调度：优先级、并发 | 全局并发上限、队列、等待、容量模式 | | `priority`、`maxConcurrentRequests` | account 字段 |
| 调度：重试、冷却、自动禁用、质量评分 | ✓ | | `autoDisablePolicy`、`preOutputStreamRetryMode` 可覆盖 | account 覆盖 |
| 传输：超时、流保活、首输出超时、流响应模式 | ✓ | | ✓ `overrides.{requestTimeoutSecs, streamIdleTimeoutSecs, streamFirstOutputTimeoutSecs, streamResponseMode}` | account 覆盖 |
| 传输：头部画像、TLS、代理 | 默认代理 | | ✓ | account 字段 |
| usage 放大与成本下限（uplift、costFloor） | ✓ | | ✓ `overrides.usageUplift` | account 覆盖 |

`AccountOverrides` 的每个字段都是 `Option`，`None` 表示继承全局。这正是现有 `streamResponseMode`、`autoDisablePolicy`、`preOutputStreamRetryMode` 已经采用的模式（`external_pool.rs:1971-1977`、`10795-10804`、`11401-11412`），只是扩展到超时和 uplift。

### 5.3 限制类字段的收紧规则（C10）

| 字段 | 规则 |
|---|---|
| 模型允许 | 路由 `modelRule` ∩ 账号 `supportedModels`，任一拒绝即拒绝 |
| 路由允许 | 路由 `accountRule` 与账号 `routeRules` 双向都放行 |
| 并发 | 账号并发与全局并发同时满足（现有 Lua 已如此） |
| 准入 | 密钥的 `requestAdmission` 不能高于全局 |
| usage 最终上下限 | 路由策略里的 bounds 是最终约束；账号的 uplift 在 bounds 之内生效，收口后不再改写（C1） |

### 5.4 解析时机

启动和每次配置变更时，`RuntimeConfigStore` 把 `routes[]` 预编译成按前缀长度降序的匹配表，并为每条路由算好 `ResolvedCachePolicy`、注入项、功能开关。请求路径上只做一次前缀匹配加一次账号覆盖合并，不重复解析 JSON。现有 `RequestRuntimeConfig` 按代次缓存快照的做法（`handlers.rs:975-1027`、`1626-1673`）保留，只是持有者换成 `RuntimeConfigStore`。
