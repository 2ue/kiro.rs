# Claude 账号池调度系统改造方案

目标：把 `kiro-rs` 改造成纯 Claude Code 协议（Anthropic Messages）账号的调度网关。账号以 `baseUrl + key` 接入；网关负责路由调度、模型限制与映射、优先级管理，并对下游 usage 做整形。所有 Kiro 相关能力删除。

分支 `claude-main`（原名 `fork/claude-pool`，2026-11-17 改名），worktree `../2ue_kiro.rs-claude-pool`，从 `main@8946fe38`（kiro-rs 0.0.252）切出，只单向合入 main，永不合回。独立发布：tag `claude-vX.Y.Z`，镜像 `ghcr.io/2ue/claude-pool`，门禁对 `claude-main` 触发（见根 README「分支与发布」）。

## 结论摘要

- **不需要重写调度器**。外部池已经自带完整的独立调度器（选择、Redis lease、排队、重试、冷却、质量评分、自动禁用），Kiro 的 `token_manager` 直接删除。
- **不需要重写 usage 整形**。账号侧投影链路与五个整形模块都是协议无关的纯逻辑，算法与测试零改动，只换一个输入类型和几个名字。
- **第一刀是运行时配置持有者**。配置读写、热加载、外部池入口判断目前全部挂在 Kiro 组件上，先剥离成独立的 `RuntimeConfigStore`，再删 Kiro。
- **协议默认透传**。请求体保留原字节；模型映射、beta 兼容和已有缓存标记的上游 TTL 固定为 5m 属于必要处理。路由“写入时长”仅控制下游 usage 展示（见 [05 第 3.3 节](05-usage整形与缓存策略.md#33-上游请求-ttl-与下游展示-ttl)）；其他改写由默认关闭的路由功能控制。14 个 Kiro 能力补偿模块删除。
- **路由收口**。五张按前缀的 `pathOverrides` 表合并为一个 `routes[]`，保留最长前缀匹配和五个内置前缀，现网客户端不改地址。
- **全新 schema，配置包迁移**。删 12 张 Kiro 表，账号表改名；现网通过导出/导入配置包迁移账号、配置、密钥，导入前输出行为差异报告。
