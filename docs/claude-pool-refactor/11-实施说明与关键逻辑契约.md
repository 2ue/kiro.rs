## 3. 关键逻辑的精确规则

以下规则逐条对应现有实现，实现者不得"优化"或"顺手修正"。每条标注现有位置以便核对。

### 3.1 路由匹配

输入 endpoint（如 `/cc/v1/messages`、`/v1/messages`、`/dfcache/foo/v1/messages`），输出命中的路由。

1. 路由前缀归一化（`config.rs:7000-7016`）：trim；为空返回 None；不以 `/` 开头则补 `/`；去掉末尾全部 `/`；结果为空则为 `/`。
2. 匹配（`config.rs:7019-7027`）：前缀为 `/` 时匹配一切；否则 `endpoint == prefix` 或 `endpoint` 以 `prefix` 开头且紧接着的字符是 `/`。
3. 多条命中取**前缀最长**的一条；长度相同不可能同时存在（保存时拒绝重复前缀）。
4. 内置路由：`""`（归一化后为 `/`，表示根 `/v1`）、`/cc`、`/ha`、`/na`。用户不能删除内置路由，可以修改其策略。
5. 根路由 `/` 作为兜底总是存在，所以任何 endpoint 都有路由；但 `/dfcache/{name}` 这类**非内置前缀**，若没有对应路由定义则返回 404（沿用 `handlers.rs:7936-7963` 的现有行为），不落到根路由。实现方式：axum 层只注册 `/v1`、`/cc/v1`、`/ha/v1`、`/na/v1` 和 `/{route}/v1` 五组；`/{route}/v1` 组内先查路由表，查不到即 404。

### 3.2 账号与路由的双向规则

规则归一化 `normalize_route_rule`（`config.rs:7062-7081`）：trim；空返回 None；`*` 原样；不以 `/` 开头补 `/`；去末尾 `/`；转小写；空则 `/`。

匹配 `route_rule_matches(rule, endpoint)`（`config.rs:7092-7108`）：`*` 匹配一切；endpoint 小写后等于 rule，或以 rule 开头且下一个字符是 `/`（rule 以 `/` 结尾时不要求）。

三态 `mode`：`allow_all` 永远放行；`allow_list` 至少一条规则命中才放行，**空列表等于不放行**；`deny_list` 任一命中即拒绝，空列表等于全放行。

候选条件：路由 `accountRule` 对账号 id（规则值写账号 id 或 `*`）放行，**且**账号 `routeRules` 对 endpoint 放行。两者任一不放行则该账号不是候选。

### 3.3 模型放行

账号 `supportedModels` 为空表示不限。非空时把请求模型与列表都做变体展开后求交集（`external_pool.rs:12052-12290`）。展开规则：

1. `normalize_model_id`：trim、小写、去掉 `anthropic/` 等已知前缀。
2. 拆后缀：`-thinking`、`[1m]` 分别记录为标志，得到 base。
3. 若 base 能对应到已知 Claude 官方模型（`official_claude_model_reference`），用 `expand_claude_supported_model_variants` 展开：点号版本与横杠版本互转、带日期与不带日期互转、去 `claude-` 前缀的短名。列表侧再加同族别名（如 `claude-opus-4`→`opus`）。
4. 每个变体再套回后缀。

路由 `modelRule` 用同样的三态与展开规则，但规则值支持尾部 `*` 通配（`claude-opus-*`），通配只对归一化后的 base 做前缀比较。

### 3.4 上游 URL

`external_pool_messages_url`（`external_pool.rs:11886-11910`）：解析 `baseUrl`；去掉路径末尾 `/`；若最后一段忽略大小写等于 `v1` 则追加 `/messages`，否则追加 `/v1/messages`；保留原 query；账号 `appendBetaQuery` 为 true 或头部画像是 `anthropic_passthrough` / `claude_code_mimic` 时设置 query `beta=true`（已存在则替换）。`count_tokens` 同理追加 `/messages/count_tokens`，`models` 追加 `/models`。入口 endpoint 不参与拼接。

### 3.5 请求头

逐条照搬 `external_pool.rs:11921-12035`、`12562-12734`：

- **generic**：转发下游全部头，排除：`host`、`connection`、`content-length`、`transfer-encoding`、`keep-alive`、`proxy-authenticate`、`proxy-authorization`、`te`、`trailer`、`upgrade`、`authorization`、`x-api-key`、`x-goog-api-key`、`cookie`、`accept-encoding`。
- **anthropic_passthrough**：只转发白名单：`accept`、`x-stainless-*`（9 个）、`anthropic-dangerous-direct-browser-access`、`anthropic-version`、`x-app`、`anthropic-beta`、`accept-language`、`sec-fetch-mode`、`user-agent`、`content-type`、`x-claude-code-session-id`、`x-client-request-id`。
- **claude_code_mimic**：固定头集合 `CLAUDE_CODE_MIMIC_HEADERS` 与 `CLAUDE_CODE_MIMIC_BETA_HEADER`，流式加 `x-stainless-helper-method: stream`，每次生成新的 `x-client-request-id`。
- 三者之后：无 `anthropic-version` 则补 `2023-06-01`；按 `authType` 写 `Authorization: Bearer <key>` 或 `x-api-key: <key>`；应用 `headerOverrides`（先 remove 再 insert）。
- `headerOverrides` 黑名单（保存与应用时都检查）：上述 generic 排除列表全部，再加 `content-type`、`proxy-connection`、`sec-websocket-*`（5 个）、`session_id`、`conversation_id`、`x-codex-turn-state`、`x-codex-turn-metadata`、`chatgpt-account-id`、`x-claude-code-session-id`、`x-client-request-id`、`x-grok-conv-id`。最多 32 条，名 ≤ 128 字节，值 ≤ 4096 字节。
- `anthropic_passthrough` 与 `claude_code_mimic` 还会：当 `anthropic-beta` 不含 `context-management-2025-06-27` 时从 body 删除顶层 `context_management`；用 `metadata.user_id` 中的 session 片段同步 `x-claude-code-session-id`（`external_pool.rs:12736-12798`）。这两项属于"必要处理"。

### 3.6 请求体改写契约（BodyPatch）

```rust
pub struct BodyPatch { pub pointer: String /* RFC 6901 */, pub op: PatchOp }
pub enum PatchOp { Set(serde_json::Value), Remove }
```

- 入口阶段的路由功能和账号阶段的模型映射都只产出 `Vec<BodyPatch>`，不直接改 body。
- patch 列表为空：**不解析 JSON**，原字节直达上游。
- 非空：`serde_json::from_slice::<Value>`（启用 `preserve_order`），按顺序应用，`serde_json::to_vec` 序列化。同一 pointer 后者覆盖前者。
- 解析失败（下游发来的不是合法 JSON）：放弃全部 patch，原字节转发，由上游报错。日志 warn 一条。
- 允许的 pointer 白名单：`/model`、`/max_tokens`、`/thinking`、`/thinking/*`、`/output_config/*`、`/system`、`/system/*`、`/messages/*`、`/tools/*`、`/context_management`、`/metadata/*`。超出白名单的 pointer 在开发期 panic（debug_assert），生产期忽略并 error 日志。这是防止将来有人把新的改写塞进透传链路的机械约束。
- `account/body.rs` 保留现有 `prepare_raw_request` 的 `rewrite_top_level` 实现作为 `/model` patch 的特例快路径：只有这一个 patch 时用现有的字节级顶层 `model` 替换，不做完整 JSON 往返。

### 3.7 流式处理

- **事件边界**：按 `\n\n` 或 `\r\n\r\n` 切分（`find_sse_event_delimiter`）。
- **首个语义输出**（`external_pool.rs:10734-10790`）：某事件 `data:` 的 JSON `type` 为 `content_block_delta` 且 `delta.type` 为 `text_delta`/`thinking_delta`/`input_json_delta` 且对应字段非空；或 `type` 为 `content_block_start` 且 block 为 `tool_use`/`server_tool_use`；或 `type` 为 `message_stop`。`message_start`、`ping`、空 text 不算。
- 首输出之前的事件缓冲在内存；首输出出现后一次性下发缓冲并进入透传。缓冲期内发生 error 事件、断流、idle 超时、首输出超时（`streamFirstOutputTimeoutSecs`）时按 `preOutputStreamRetryMode` 换号，下游无感。
- 首输出之后出现 error 事件：转发脱敏后的 error 事件并结束，不换号。
- **usage 槽位**（`external_pool.rs:14745-14812`）：对每个 `data:` JSON，依次看顶层 `usage`、`message.usage`、`delta.usage`。`message.usage`（即 `message_start`）只预览不提交；顶层 `usage` 或 `delta.usage`（即 `message_delta`）提交缓存与频次状态。顶层 `usage` 存在时不再看 `delta.usage`。
- **保活**：缓冲期与空闲期每 `max(1, streamIdleTimeoutSecs/2)` 秒向下游发一个 `: keepalive\n\n` 注释帧；一旦有上游数据则不发。下游收到的注释帧按 SSE 规范被忽略。
- **事件改写只允许三种**：error 事件脱敏、usage 字段改写、换号后重复 `message_start` 丢弃（early_commit）。路由功能 `historySanitize` 开启时允许第四种：`ToolTranscriptSanitizer` 对 `text_delta` 的清洗。

### 3.8 usage 投影输入与提交

- `UpstreamUsage` 从上游 `usage` 对象读取：`input_tokens`、`output_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens`、`cache_creation.ephemeral_5m_input_tokens`、`cache_creation.ephemeral_1h_input_tokens`。缺失字段为 0。另外兼容 OpenAI 风格 `prompt_tokens`/`completion_tokens`（现有 `normalize_external_usage_value`）。
- `shaping::usage_from_upstream(u: Option<&UpstreamUsage>, estimated_input, estimated_output) -> CacheUsage`，替代 `cache.rs:2215-2265`：无上游 usage 时 input=估算、cache 为 0；有上游 usage 时 output 取上游（为 0 时取估算），`cache_read`、`cache_creation` 取上游（负数归 0），`input` 取上游 `input_tokens`（为 0 时用 估算 - cache_read - cache_creation，下限 0），`total_input = input + read + creation`，5m/1h 拆分取上游（都为 0 时 5m = creation）。
- 投影顺序严格按 [05 第 3 节](05-usage整形与缓存策略.md#3-账号侧投影顺序)。
- 基准输入 `request_input_tokens` 用本地 `token::count_all_tokens` 对原始请求体估算（`usage_projection.rs:290-299`），**不是**上游 `input_tokens`。
- 只有成功终止（流式收到 `message_stop` 或非流式 2xx 完整体）才 `commit`；换号前的失败尝试不提交。

### 3.9 稳定会话 id

搬运 `converter.rs:353-400`：优先 `metadata.user_id`（现有 `extract_metadata_conversation_id` 会从 Claude Code 的 `user_xxx_account_xxx_session_xxx` 形式中取 session 段）；没有则对 `{system, tools, first_user_message}`（无 user 消息时用全部 messages）做 canonical JSON 后 SHA-256，取前 16 字节按 UUIDv5 格式化。哈希前缀字符串从 `kiro.rs:anthropic:conversation-id:v1:` 改为 `claude-pool:anthropic:conversation-id:v1:`。前缀追踪器是进程内存，改前缀不影响持久数据。

缓存 scope = `(conversation_id, route_namespace)`，账号维度通过 `credential_key = "account:{id}"` 进入频次控制器（`usage_projection.rs:150`）。

### 3.10 错误分类与对外映射

分类顺序（`external_pool.rs:13382-13591`，按 body 小写文本与状态码）：

1. 文本含 `too many requests` / `service_request_rate_exceeded` / `rate limit` / `ratelimit` → `rate_limit`，可重试，冷却取 `retry-after` 否则 `rateLimitCooldownSecs`。
2. 含 `database is locked` / `sqlite_busy` → `database_busy`，可重试。
3. 含 `invalid token` → `auth_error`，可重试，自动禁用原因 `auth_error`。
4. 含 `channel affinity` 且 `disabled` → `channel_disabled`，可重试，自动禁用原因同名。
5. 模型不可用文本，或 404 且 invalid model 文本，或 Anthropic 官方格式 404 `not_found_error`（message 以 `model:` 开头）→ `model_unavailable`，可重试，按 `modelUnavailableCooldownMode` 决定冷却。
6. 400 → `bad_request`，**不可重试**；其中图片过大、payload 过大、上下文满三种子类有专门文案；上下文满在路由开启 `payloadGuard` 时允许裁剪后重试一次。
7. 429 → `rate_limit`。
8. 401/403 → 文本含 `suspended`/`risk`/`locked`/`security precaution` 为 `security_lock`，否则 `auth_error`；可重试；自动禁用原因同名。
9. 402 或文本含 `quota`/`insufficient credit`/`insufficient balance`/`billing`/`payment required`/`no credit`/`not enough credit` → `quota_exhausted`，可重试，自动禁用原因同名。
10. 5xx 或 408 → `server_error`，可重试。
11. 其余 → `upstream_error`：裸 404（正文没指明模型问题，多为账号地址或路径配错）标为可重试、不写冷却、不自动禁用、不计入账号质量，是否换号由 `retryStatusCodes`（默认含 404）决定；其它状态不可重试。

对外映射（`external_pool.rs:1709-1760`，保留现有实现，只改一处）：

| 条件 | 状态码 | error.type | 文案 |
|---|---|---|---|
| rate_limit | 429 | `rate_limit_error` | 固定公开文案 |
| 400 且不可重试 | 400 | `invalid_request_error` | 图片过大 / payload 过大 / 上下文满 / 通用四选一的固定文案 |
| 容量类（无候选、排队超时、全局并发满）与上游过载（503 / 529） | **529** | **`overloaded_error`** | "服务繁忙"固定文案 |
| 其余 | 502 | `api_error` | 固定公开文案 |

所有对外错误带 `x-error-id`，文案末尾附 error id；上游原始错误体只写入 usage 记录的 `raw_upstream_error` 和日志，**不透传给下游**。这是对 [02 第 5 节](02-目标架构与请求链路.md#5-错误出口) "最后一次上游错误脱敏后原样返回" 的修正：沿用现有固定文案方案，因为它已经过现网验证且不会泄露账号信息。

### 3.11 调度默认值与排队

- 候选为空且原因是"全部冷却/并发满"时进入排队；原因是"全部被路由或模型拒绝"时立即 404。
- `capacityMode=wait`：进入 Redis 全局队列，上限 `maxQueuedRequests`(256)，等待 `dispatchMaxWaitSecs`(60)；每次被 `events:dispatch_wakeup` 唤醒或每 500ms 重新执行一次候选过滤与 lease。
- coordinator 熔断打开：跳过 Redis 队列与 lease，用进程内信号量（每账号 `maxConcurrentRequests`，全局 `globalMaxConcurrentRequests`），等待同样受 `dispatchMaxWaitSecs` 约束。

### 3.12 配置合并

```
effective(field) =
  account.overrides.field        if Some
  else global.accounts.field
```

路由策略不与全局合并，路由里的 `cachePolicy` 与 `reportedUsage` 本身就是完整的补丁，解析方式沿用 `resolve_cache_policy_for_path`（`config.rs:3850-3904`）：legacy 基础值 → 路由 reportedUsage → 按 cacheType 取全局模板 → 路由补丁。

`usageProjectionMode=pass_through` 的账号跳过整形但仍记录 raw usage 与计费。

## 4. 红线（不可越界）

实现过程中任何改动若触碰以下任一条，必须停下并回到文档层面讨论，而不是在代码里"先做了再说"：

1. **不新增任何协议转换**。入口只接受 Anthropic Messages，出口只发 Anthropic Messages。不做 OpenAI、Gemini、Bedrock 等任何形式的入口或出口适配。
2. **不新增默认开启的请求/响应改写**。任何改写要么是第 3 节列出的必要处理，要么是默认关闭的路由功能并通过 `BodyPatch` 白名单。
3. **不改 usage 整形算法**。`shaping/` 下的函数体与 `main` 上对应代码逐行一致，只允许改名、改入参类型、搬文件。golden 测试不一致即为回归。
4. **不按路径名写死行为**。代码中不得出现 `if endpoint.starts_with("/cc")` 这类判断；一切差异来自路由定义。内置路由的默认值放在配置默认值里，不放在请求路径代码里。
5. **不重新引入"本地/外部"二分**。不存在第二种上游类型；`UpstreamKind`、`fallback`、`rescue`、`direct policy` 这些概念不得以任何新名字复活。
6. **不保留 Kiro 命名**。除 [01 第 6 节](01-现状盘点与去留清单.md#6-命名清理) 允许的导入子命令旧表名常量外，`grep -ri kiro` 必须为 0。
