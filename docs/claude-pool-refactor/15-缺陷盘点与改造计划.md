# 15. 缺陷盘点与改造计划

2026-11-18 对 claude-pool 控制台与后端做的一次全面审计（不考虑多实例）。本章只记录**仍未修复**的缺陷与改造顺序；已修复项从这里删除并在第 14 章发布记录里体现。

审计范围：ui/src/features 下 13 个页面、src/admin、src/account、src/storage、src/anthropic/usage。对照基准是 main 分支（`../2ue_kiro.rs`）同名页面与接口。

## 4. 统计维度缺口

## 5. 实现缺陷

### 5.1 调度与存储

批次 B 已收口的点不再列出。剩余约束：汇总表 `usage_rollup_time_buckets` 的账号/模型/路由等维度随时间单调增长，目前只靠小时桶压缩（维护命令）控制体积；明细保留开启后会话维度汇总按最后活跃时间裁剪，其它维度不裁。

### 5.2 审计与校验

- 未写审计：明文采集 start/stop/download（`capture_handlers.rs:52,64,81`）、带密钥导出（`config_transfer.rs:462`）、`promote_account_models`；失败的变更一律不留痕；管理端认证失败不记录不限速（`middleware.rs:81`）。
- `GET /config/runtime` 明文返回全局 `proxyPassword`（账号级代理是打码的）。
- 后端不校验：`usageProjection*` 百分比与阈值可为负（`service.rs:4037`）；新建账号 apiKey 可为空，落库后被静默跳过，UI 显示启用实际永不调度（`postgres.rs:1714`、`1562`）；`maxConcurrentRequests` 无上限，`u32 as i32` 溢出成负数；全局代理格式不校验。
- 删路由不检查请求 Key 的 `allowedRoutes` 引用（`management.rs:295`）；路由场景应用绕过 `normalize_routes` 的模型通配符检查（`service.rs:4007`）。

### 5.3 配置热更新

- `usageRecordLimit` 改后只是显示变了，实际不生效（`main.rs:328` 启动时固定）。
- `tlsBackend` 只在启动时读且账号转发根本不用；"生效参数"抽屉仍把它当生效项。
- 模型发现与账号测试不走代理、不用 Header/TLS profile，测试结果与真实转发不一致（`service.rs:1133`、`1302`）。

### 5.4 错误出口

- 过载三种表示并存：529 overloaded、503 overloaded、503 api_error。
- `body_processing.rs:285,452,670,773` 的 reqwest 错误（含 URL、DNS）原样以 400 返回下游。
- `account/mod.rs:13020`：透传上游 `anthropic-ratelimit-*` 响应头，暴露上游配额。

### 5.5 测试覆盖

管理端 HTTP 处理器几乎无直接测试；路由场景、明文采集、配置导入导出处理器层、`usage_projection.rs` 整个模块、`forward_with_failover`、决定对外状态码的分类函数（`is_rate_limit` 等）均无测试引用。

### 5.6 流式结束归因（已在 1.0.6 修复）

现象：下游读到 `message_stop` 就关连接（sub2api 账号测试、部分 SDK），claude-pool 在上游 EOF 之前看到下游断开，记成 `client_dropped` 且 usage 归零。根因与取证见 14 章第七次发布记录。

修法：`ExternalStreamUsageGuard` 记录"已向下游转发终止事件"，`Drop` 时若已见终止事件按 success 落账并保留 usage。main 的外部池路径（`src/external_pool.rs`）与此处代码相同，同样受影响，补丁尚未同步给 main。
