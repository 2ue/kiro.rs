# 15. 缺陷盘点与改造计划

2026-11-18 对 claude-pool 控制台与后端做的一次全面审计（不考虑多实例）。本章只记录**仍未修复**的缺陷与改造顺序；已修复项从这里删除并在第 14 章发布记录里体现。

审计范围：ui/src/features 下 13 个页面、src/admin、src/account、src/storage、src/anthropic/usage。对照基准是 main 分支（`../2ue_kiro.rs`）同名页面与接口。

## 1. 改造顺序

按用户决定：**每一批做完先发版，再做下一批**。

| 批次 | 内容 | 状态 |
|---|---|---|
| 批次 A（1.0.5） | 表单样式收口；路由加 id、编辑页 URL 不再带前缀；模型目录内置 Fable/Mythos 等、从公信力来源同步并弹层确认、列表加序号、对外 `/v1/models` 只返回目录里 listed 的真实模型 | 已发布 claude-v1.0.5 |
| 批次 B（1.0.6） | 稳定性：协调 epoch 超时与锁泄漏、总览聚合走汇总表、usage 保留任务、嵌套路由 endpoint 剥前缀、排行账号页为空、流式 client_dropped 误判 | 已发布 claude-v1.0.6 |
| 批次 C（1.0.7） | 误操作防护：破坏性操作确认、未保存拦截、审计搜索改服务端、安全页错误态、策略模板只提交本模板、场景预览失败可重试 | 已发布 claude-v1.0.7 |

## 3. 表单样式缺陷

- 安全页"新增 / 编辑请求 Key"弹窗与风控页查询条件仍用各自的 label 排版（风控页自定义了同名 `Field`），没有换成 `@/components/patterns` 的共享 `Field`。
- 宽表写死最小宽度：总览账号表 `min-w-[1500px]`、用量明细 `min-w-[1280px]`，1280 宽必须横滚且操作列在最右。

## 5. 实现缺陷

### 5.1 调度与存储

汇总表 `usage_rollup_time_buckets` 的账号/模型/路由等维度随时间单调增长，目前只靠小时桶压缩（维护命令）控制体积；明细保留开启后会话维度汇总按最后活跃时间裁剪，其它维度不裁。账号质量分快照表 `account_quality_samples` 每账号每分钟最多一行，固定保留 7 天。

### 5.2 审计与校验

管理端认证失败只写审计（按真实连接地址每分钟最多 10 条、全局 60 条，被压掉的次数并入下一条），不对尝试本身限速或封禁：经反向代理部署时所有请求的连接地址都是代理，按地址封禁会误伤管理员；代理头可伪造，只作参考记录。

### 5.3 测试覆盖

管理端 HTTP 处理器直接测试仍少；路由场景、明文采集、配置导入导出处理器层、`usage_projection.rs` 整个模块、决定对外状态码的分类方法（`AccountFinalError::is_rate_limit` 等）没有测试引用。
