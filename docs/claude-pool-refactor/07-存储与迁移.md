# 07 存储与迁移

## 1. 原则

新分支使用**全新 schema**（D4）：删除所有 Kiro 表，改名外部池表，重置 `schema_migrations` 与 `runtimeConfigMigrationVersion`。不在新代码里保留对旧表的读取兼容；现网数据通过导出/导入配置包迁移（C11）。

## 2. PostgreSQL

### 2.1 删除

`credentials`、`credential_account_info`、`credential_events`、`credential_inventory`、`credential_runtime_mutations`、`credential_runtime_state`、`credential_stats`、`credential_stats_delta_batches`、`credential_kiro_api_keys`、`kiro_version_state`、`usage_credential_cost_summary`、`proxy_resources`。

对应的 `SCHEMA_SQL`（`postgres.rs:13531-14389`）段落、`storage/credential_inventory.rs`、`storage/kiro_api_keys.rs`、以及 5 个 `credential-*-v1` 迁移一并删除。

### 2.2 改名与改列

| 表 | 变更 |
|---|---|
| `external_upstream_pools` → `accounts` | 删列 `skip_non_stream_usage_projection`、`preserve_path`、`request_body_mode`、`raw_model_mode`；新增 `tags TEXT[]`、`proxy_url TEXT`、`cost_multiplier DOUBLE PRECISION DEFAULT 1`、`overrides JSONB DEFAULT '{}'` |
| `usage_records` | `credential_id` → `account_id`、`credential_label` → `account_label`；删 `kiro_metering_usage`、`sticky_bound`、`fallback_from_sticky`；`data->>'externalPoolId'` 索引改 `accountId`；新增 `account_cost_usd` |
| `usage_rollup_totals`、`usage_rollup_time_buckets` | 删 `total_kiro_metering_usage`；`external_pool_*_cost_usd` → `account_*_cost_usd` |
| `model_capabilities` | 删 `reasoning_cohort_*`；新增 `listed BOOLEAN DEFAULT true` |
| `model_capabilities_sync_status` | 只记录账号发现时间与结果 |
| `runtime_config` | 结构不变；协调 epoch 行 id `external_pool_redis_coordination_epoch` → `account_redis_coordination_epoch` |
| `route_scenarios` | `content` JSON 删 `local`、`localAccounts` |
| `admin_audit_logs` | `detail.accountEvent.kind` 删 `local` 取值 |

### 2.3 保留不动

`model_pricing`、`model_pricing_sync_status`、`usage_cleanup_watermarks`、`usage_cleanup_jobs`、`usage_cache_read_totals`、`usage_cache_read_rollup_time_buckets`、`usage_duration_rollup_time_buckets`、`schema_migrations`。

| `admin_cache:external_pools:*` | 改 `admin_cache:accounts:*` |

`redis_cache.rs` 中共用的 `InFlightKeys` 与 Lua 脚本（`:7716-7795`、`:4701`）保留，只删 `scheduler:` 一侧的构造函数。

## 4. 从现网 kiro-rs 迁移

现网 59137 实例（见 memory）同时跑 Kiro 本地账号和外部池。迁移到新系统只搬三类数据：账号、运行时配置、下游密钥。usage 历史不迁移（见 [10 Q8](10-待确认事项.md)）。

### 4.1 导出（在旧版本上执行）

现有 `feat/config-package` 已合入 main，提供配置包导出导入（按自然键匹配、导入全量覆盖、机器本地字段不导出）。新增一个旧版本侧的子命令 `kiro-rs export-pool-package`（这是唯一允许保留 Kiro 字样的地方，因为它运行在旧二进制里），输出 JSON：

```jsonc
{
  "formatVersion": 1,
  "exportedFrom": "kiro-rs 0.0.252",
  "accounts": [ /* external_upstream_pools 全部字段，api_key 明文 */ ],
  "runtimeConfig": { /* runtime_config.config 原样 */ },
  "requestApiKeys": [ /* requestApiKeyPolicies */ ],
  "routeScenarios": [ /* route_scenarios，含 local 部分 */ ],
  "modelPricing": [ ... ],
  "manualModels": [ ... ]
}
```

### 4.2 导入（在新版本上执行）

`claude-pool import-pool-package <file>` 做以下映射，并输出一份人类可读的差异报告再写库：

| 旧 | 新 | 规则 |
|---|---|---|
| `accounts[]` | `accounts` 表 | 字段同名直接搬；`request_body_mode`、`raw_model_mode`、`preserve_path` 丢弃并在报告中列出；`usage_projection_mode` 保留旧值（不改为新默认） |
| `runtimeConfig.externalPools.externalPoolXxx` | `accounts.xxx` | 去前缀；第 01 章 3.1 节列出的本地相关字段丢弃并列出 |
| `runtimeConfig.cachePolicy.pathOverrides[p]`、`reportedUsage.pathOverrides[p]`、`promptInjection.pathOverrides[p]`、`routeFeatures.pathOverrides[p]` | `routes[prefix=p]` | 按前缀合并为一条路由；`definedCacheRoutes` 的每一项生成 `/dfcache/{name}` 路由 |
| `cachePolicy.kiroRsTool`、`kiroRsToolPlus`、`cacheType: kiro_rs_tool(_plus)` | `prefixTool`、`prefixToolPlus`、`prefix_tool(_plus)` | 改名 |
| `cachePolicy.*.cachePoint`、`cacheTtl.local` | 丢弃 | 列出 |
| `promptInjection.defaults[x].externalPool` | 丢弃 | 保留项的 `enabled` 直接生效；原来 `externalPool=false` 但 `enabled=true` 的项在报告中高亮，因为行为会变 |
| 第 01 章 3.1 节的 Kiro 字段 | 丢弃 | 列出 |
| `requestApiKeys` | 同名 | 直接搬 |
| `routeScenarios[].content.local*` | 丢弃 | 其余搬 |
| `modelPricing`、`manualModels` | 同名表 | 直接搬 |

导入默认 dry-run，只输出报告；加 `--apply` 才写库。导入是全量覆盖（C12 的现有语义）。

### 4.3 行为差异提示

导入报告必须显式列出这些会改变现网行为的点，由用户确认：

1. 原来走本地 Kiro 账号的请求现在全部走账号池；若现网账号池并发总量小于原本地池，需要先调大 `maxConcurrentRequests`。
2. `promptInjection` 里原本只对本地生效的项，导入后对账号池生效（若 `enabled=true`）。
3. 请求体不再规范化：原 `normalized` 模式账号收到的 body 会与现在不同（字段顺序、占位符、budget 字段）。
4. `capacityMode` 与 `dispatchMaxWaitSecs` 的默认值变化只影响未显式配置的情况。

## 5. 日志保留与清理

现有 usage 清理任务（preview / start / status / cancel / resume）和审计日志保留天数保留。C9：所有自动清理默认关闭。
