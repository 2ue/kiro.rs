# 04 调度

调度器直接沿用 `ExternalPoolManager`（`external_pool.rs:3461`）的实现，改名 `AccountManager`。本章记录它现有的行为契约、要删除的混合调度分支，以及与 C3/C4/C5 对照后要调整的默认值。没有列出的逻辑一律不改。

## 1. 调度目标与不变量

| 编号 | 不变量 | 来源 |
|---|---|---|
| S1 | 存在"启用、未自动禁用、未冷却、路由与模型都放行、并发未满"的账号时，请求必须在本次选择中拿到 lease，不排队 | C3 |
| S2 | 没有空闲槽时进入排队，队列深度与等待时间有上限；队列推进不依赖下游密钥的并发限制 | C3 |
| S3 | 单次失败只要仍有未尝试的候选账号且错误类型可重试，就换号重试，不对外报错；向下游输出已经开始后不再换号（early_commit 模式除外） | C4 |
| S4 | Redis 不可用或变慢时，退回进程内 lease 继续调度，只按优先级与本地负载选 | C5 |
| S5 | 账号配置在"选中"与"发送"之间被修改时，放弃本次选择重新选（revision 校验） | 现有 `external_pool.rs:8712-8810` |
| S6 | 全池熔断类保护默认关闭 | C4、C14 |

## 2. 候选过滤

输入 `RouteContext`（路由 id、请求模型）和账号快照，输出候选列表。顺序与现有 `external_pool.rs:8095-8179` 一致：

1. 排除本次请求已尝试过的账号。
2. `enabled == true` 且不在自动禁用期。
3. 路由双向放行：路由 `accountRule` 允许该账号，账号 `routeRules` 允许该路由。
4. 模型放行：路由 `modelRule` 允许，且账号 `supportedModels` 为空或命中（含变体展开）。
5. 读取 Redis 运行态（一次 Lua 批量读：in_flight、全局 in_flight、冷却、模型冷却、30 秒瞬态失败数、质量样本），标注 `skip_reason`：冷却中、单账号并发满、全局并发满。

候选为空时按原因返回：全部被路由或模型拒绝 → 404 model not found；全部冷却或禁用 → 进入排队等待（而非直接 503）。

## 3. 选择算法

两套算法保留，开关是 `accounts.qualityAwareSchedulingEnabled`（默认 false）：

- **字典序**（`external_pool.rs:11164-11200`）：有效优先级 = `priority + 30 秒内瞬态失败次数 × transientFailurePriorityPenalty(20)`，越小越先；同级比负载率 `in_flight / max`；完全相同随机。
- **质量感知**（`external_pool.rs:11202-11351`）：先按有效优先级硬分层，只在最优层内算分：优先级、负载率、相对中位数的错误率、相对中位数的首字/总延迟、避让罚分，各乘权重；避让期账号保留 `probeSharePercent`(5%) 的探测流量；在分数最好的 `topK`(3) 个里按分差加权随机。避让只看与同批候选中位数的相对差，全体一起变差时不降级任何人。

本方案不引入权重字段。原因：优先级分层加负载率已经能表达"主备"和"同级均摊"两种常见需求，权重会和质量评分的加权随机叠加出难以解释的结果。若后续确有需要，作为账号字段加入字典序算法的同级随机环节。

## 4. lease 与排队

- Redis Lua 原子 lease（`external_pool.rs:8859-9075`、`redis_cache.rs:4701`）同时检查冷却、单账号并发、全局并发、协调 epoch；心跳续期；释放经后台 dispatcher 保证送达（`external_pool.rs:3526-4240`）。全部保留，key 前缀 `external_pool:` 改 `account:`。
- 容量不足：`capacityMode`
  - `wait`（**新默认**）：进入 Redis 全局队列 `account:global:queue_leases:v1`，上限 `maxQueuedRequests`，最长等待 `dispatchMaxWaitSecs`（**新默认 60**）；有槽释放时通过 `events:dispatch_wakeup` 唤醒。
  - `fail_fast`：直接返回 529。
- 调度截止时间：原来取 `max(本地等待, 外部等待, 本地救援等待)`（`request_entry.rs:25-46`），现在只剩 `dispatchMaxWaitSecs`。

## 5. 错误分类与重试

错误分类函数 `classify_external_error`（`external_pool.rs:13382-13591`）保留。分类结果：

| 类别 | 判定 | 换号 | 副作用 |
|---|---|---|---|
| `rate_limit` | 429 或关键词 | 是 | 质量样本、瞬态失败计数；冷却时长优先取 `retry-after` |
| `server_error` | 5xx、408 | 是 | 同上 |
| `auth` | 401/403 | 是 | 自动禁用计数（开关开时） |
| `quota_exhausted` | 402 或额度关键词 | 是 | 自动禁用计数（开关开时） |
| `channel_disabled`、`security_lock` | 关键词 | 是 | 自动禁用计数 |
| `model_unavailable` | 404 model 或关键词 | 是 | 按 `modelUnavailableCooldownMode` 写模型级或账号级冷却 |
| `model_mapping_miss` | 账号要求命中但未命中 | 是 | 无 |
| `misconfigured_endpoint` | HTML、非 Anthropic 信封 | 是 | 账号级硬冷却 |
| `network`、`protocol` | 无状态码 / 200 但内容异常 | 由 `retryOnNetworkError`、`retryOnProtocolError` 决定 | 质量样本 |
| `bad_request` | 400（非 prompt too long） | 否 | 无；原样返回 |
| `prompt_too_long` | 400 + 关键词 | 路由开了 payloadGuard 时裁剪后重试；否则否 | 无 |

同账号重试最多 1 次（`retry_pipeline.rs:50-78`），跨账号重试总预算 `retryMaxAttempts`(3)，再受 `inferenceUpstreamMaxAttempts` 全局预算约束。首输出前超时允许额外换 2 次（`external_pool.rs:6470-6515`）。

流式首输出前的失败（error 事件、断流、idle、首输出超时）按 `preOutputStreamRetryMode` 换号；`early_commit` 模式下先把 usage 清零的 `message_start` 发给下游，换号后丢弃重复的 `message_start`，在 `message_delta` 补回 usage（`early_commit.rs`）。

## 6. 冷却、自动禁用、质量

- 普通上游错误**不写账号级冷却**，只写 30 秒窗口的瞬态失败计数影响排序（`external_pool.rs:13378` 的现有语义）。只有 `misconfigured_endpoint` 和 `model_unavailable`（按模式）写冷却。`*CooldownSecs` 六个配置保留作为这两类的时长。
- 自动禁用：`autoDisableEnabled`(false) 总开关；`onAuthError`、`onSecurityLock`、`onQuotaExhausted`、`onMisconfiguredEndpoint`、`onChannelDisabled` 分类开关；`failureThreshold`、`windowSecs`、`durationSecs`(0 永久)。账号可用 `autoDisablePolicy` 覆盖总开关。触发时在 PG 做带 revision 条件的更新、写账号事件、广播失效（`external_pool.rs:9503-9626`）。
- 质量样本：成功记首字与总延迟，失败记错误；请求体问题和模型问题不计入。管理端可清除单账号的冷却、失败计数、质量数据（现有 `/external-pools/{id}/cooldown/clear`）。

## 7. Redis 协调与降级

- 两个进程内熔断器保留：selection（保护 PG 读）、coordinator（保护 Redis）（`external_pool.rs:2964-3460`）。
- **删除**"只有当请求是因本地 Redis 降级转来时才允许进程内 lease"的限制（`external_pool.rs:1119-1125`、`7995-8042`、`8687-8710`）。新规则：coordinator 熔断打开时，一律使用进程内信号量 lease（按账号 `maxConcurrentRequests` 和全局上限），字典序选择，跳过质量评分与跨实例排队。这是 C5 的直接要求。
- 账号快照缓存：PG 权威，fresh 250ms、stale 30s，Redis pub/sub `events:account_data_changed` 跨实例失效（`external_pool.rs:5642-5693`）。

## 9. 配置字段（`accounts.*`）

| 组 | 字段（默认） |
|---|---|
| 容量 | `globalMaxConcurrentRequests`(512 → **1024**)、`maxQueuedRequests`(10 → **256**)、`capacityMode`(wait)、`dispatchMaxWaitSecs`(60) |
| 重试 | `retryMaxAttempts`(3)、`retryStatusCodes`([404,408,425,429,500,502,503,504,529])、`retryOnNetworkError`(true)、`retryOnProtocolError`(true)、`samePoolRetryCount`(1)、`samePoolRetryStatusCodes`、`samePoolRetryDelayMs`(500)、`transientFailurePriorityPenalty`(20) |
| 质量 | `qualityAwareSchedulingEnabled`(false)、`qualityEwmaAlpha`(0.2)、`qualitySampleTtlSecs`(600)、`qualityMinSamples`(5)、五个权重、`qualityTopK`(3)、`degradeWindowSecs`(120)、`degradeErrorRateThreshold`(0.5)、`degradeProbationSecs`(180)、`maxProbationSecs`(900)、`probeSharePercent`(5)、`recoveryRampSecs`(60) |
| 自动禁用 | 9 项，默认同现有 |
| 冷却 | `rateLimit/serverError/networkError/protocolErrorCooldownSecs`(30/10/10/10)、`modelUnavailableCooldownMode`(disabled)、`modelUnavailableCooldownSecs`(10) |
| 超时与流 | `requestTimeoutSecs`(180)、`streamRequestTimeoutSecs`(0)、`streamIdleTimeoutSecs`(180)、`streamFirstOutputTimeoutSecs`(120 → **45**)、`streamPreOutputRetryEnabled`(true)、`streamResponseMode`(event_passthrough) |
| 诊断 | `usageDebug*`(4)、`wireDebug*`(4)，目录默认 `/tmp/claude-pool/` |

`maxQueuedRequests` 从 10 提到 256、`globalMaxConcurrentRequests` 从 512 提到 1024：账号池队列不应比入口队列更小，否则入口放进来的请求在账号层被拒绝；高并发默认按"几十到上百个账号 × 4 并发"的池子设，队列 256 在 60 秒等待内可被 40 槽 × 5 秒/请求的吞吐消化。`streamFirstOutputTimeoutSecs` 从 120 降到 45：挂起流（上游只发 message_start 后无输出）在首输出前可换号重放，45 秒明显短于常见客户端 120 秒超时，让换号发生在客户端放弃之前；真实上游首字一般在 1 到 10 秒。
