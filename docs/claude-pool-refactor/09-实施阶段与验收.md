# 09 实施阶段与验收

## 1. 分支与工作区

- 分叉分支 `fork/claude-pool`，从 `main@8946fe38` 切出，worktree `../2ue_kiro.rs-claude-pool`。
- 该分支是独立主线：**只从 main 单向合入，永不合回 main**（与 `forced-main` 分支同样的约定）。
- 版本号从 `1.0.0` 起，与 kiro-rs 的 `0.0.x` 序列脱钩。
- 所有代码与文档只写在该 worktree；main 工作区不动。

## 2. 阶段划分

每个阶段结束时必须 `cargo build`、`cargo test` 全绿，并在该阶段的 commit 中附带验证记录。阶段顺序按依赖关系排列，不能并行的点已标注。

### 阶段 0：行为冻结（在 main 上记录，不改代码）

1. 用现网脱敏配置构造 golden 数据：对 `external_pool/tests.rs` 里已有的 usage 投影测试补一组"固定请求 + 固定上游 usage + 固定策略 → reported usage"的快照文件，覆盖六种策略类型、流式与非流式、有无读取证据、有无上游 1h 写入。
2. 记录 `external_pool/tests.rs` 中调度相关测试的清单，作为阶段 3 的回归集。
3. 记录现网 `runtime_config` 的字段清单（脱敏），作为阶段 6 导入映射的输入。

### 阶段 1：剥离运行时配置持有者

目标：`RuntimeConfigStore` 独立，所有读写不再经过 `MultiTokenManager` 与 `KiroProvider`。

- 新建 `model/runtime.rs`：加载、保存递增版本、Redis 热加载监听、带代次的快照。
- `handlers.rs:1626-1673` 的 `request_runtime_config`、`live_runtime_config` 改为从 store 取。
- `admin/service.rs` 的 `runtime_config()` 调用（`:6903`、`:7127`、`:7510-8036`、`:11526`、`:11626`）改为 store。
- `main.rs:1566-1660` 的热加载改为 store。
- 此阶段 Kiro 代码仍在，但不再是配置的持有者。全部测试应仍通过，这是验证剥离正确性的方式。

### 阶段 2：删除 Kiro（依赖阶段 1）

目标：`src/kiro/` 目录不存在，编译通过。

删除顺序（从叶子到根，每删一组就编译一次）：

1. `admin/`：删 Kiro 端点、`inventory.rs`、`public_pool.rs`、`AdminService` 的 `token_manager` / `kiro_provider` 字段；`route_scenarios.rs` 删 local。
2. `anthropic/handlers.rs`：删本地流式/非流式、重试、回落、本地 usage 整形、WebSearch 分支、`local_body_pipeline`、`model_driven_websearch`；入口直接调用账号池。
3. `anthropic/`：删 `converter*`、`stream.rs`、`websearch.rs`、`files.rs`、`openai/`、Kiro 能力补偿层 14 个文件（[01 第 2.2 节](01-现状盘点与去留清单.md#22-srcanthropic)）；`cache.rs` 入参换 `UpstreamUsage`；`model_capabilities.rs` 删同步与 cohort。
4. `external_pool.rs`：删 `local_attempts`、直连策略、Redis 降级限制。
5. `model/config.rs`：删第 01 章 3.1 节的字段；`ExternalPoolsConfig` 删本地字段；迁移版本重置为 1。
6. `storage/`：删 Kiro 表与 Redis key；`account_events.rs` 删 local。
7. `main.rs`：删 Kiro 装配。
8. `src/kiro/` 整体删除；`storage_task.rs` 先迁到 `common/`。
9. `bin/kiro_loadtest.rs` 删假 Kiro 上游。
10. `Cargo.toml`：删除只被 Kiro 使用的依赖：`ciborium`（`kiro/portal.rs`、`token_manager/refresh.rs`）、`crc`（`kiro/parser/*`、`debug.rs`、压测假上游）、`pdf-extract`（`converter/content.rs`）。`zip` 被 `diagnostics/capture.rs` 使用，保留。

验收：`cargo build` 通过；`grep -ri kiro src/` 只剩待改名项；阶段 0 的 golden 测试通过。

### 阶段 3：透传改造与路由功能化（依赖阶段 2）

- `body_pipeline.rs`：删 `normalized` 模式，实现 `BodyPatch` 机制。
- `request_entry.rs`：raw 探测改为只读；缺省 max_tokens、reasoning 归一、历史清洗改为路由功能。
- `parsed_body_pipeline.rs`：thinking 模型名、thinking 触发、多模态物化改为路由功能。
- `payload_guard`：删 Kiro 权重部分，剩余改为路由功能。
- 响应侧：`ToolTranscriptSanitizer` 与 thinking 块缓冲改为路由功能。
- 错误出口按 [02 第 5 节](02-目标架构与请求链路.md#5-错误出口) 调整（529、最后一次上游错误）。

验收：对每个路由功能写"开启时改写、关闭时字节一致"的成对测试；用 `pool_loadtest` 的假上游断言关闭全部功能时请求体与下游原字节逐字节相同。

### 阶段 4：路由定义与配置分层（依赖阶段 3）

- `config.rs`：新增 `routes[]`，删五张 `pathOverrides` 表与 `definedCacheRoutes`；写旧结构到新结构的迁移函数。
- `AccountOverrides` 与合并逻辑。
- 账号表加列、删列。
- 调度默认值调整（`capacityMode`、`dispatchMaxWaitSecs`、`maxQueuedRequests`）。
- Redis 降级规则改为"熔断开则进程内 lease"。

验收：`config.rs` 单测覆盖迁移函数；路由匹配与账号覆盖的合并写 table-driven 测试；调度回归集通过。

### 阶段 5：改名（依赖阶段 4）

包名、环境变量、Redis 前缀、配置键、策略 id、表名、API 路径、前端文案。全部一次完成并提交一个 commit，便于 diff 审查。

验收：`grep -ri kiro` 在第 01 章第 6 节列出的范围内为 0（导入子命令的旧表名常量除外）。

### 阶段 6：迁移工具（可与阶段 5 并行）

- `claude-pool export-legacy --from-postgres <旧库>`：新二进制直连旧 kiro-rs 的 PostgreSQL 导出，不改旧版本、不碰 main。
- `claude-pool import-legacy <file> [--apply]`：dry-run 报告与 `--apply`。

验收：用现网脱敏导出包做 dry-run，报告中的丢弃字段与行为差异提示与 [07 第 4 节](07-存储与迁移.md#4-从现网-kiro-rs-迁移) 一致；`--apply` 后 golden 测试在导入的配置上通过。

### 阶段 7：管理 API 与控制台（依赖阶段 4、5）

- 后端：删、改名、新增端点。
- 前端：删页面、改名、新增路由页、拆分 api/hooks/types。

验收：`pnpm --dir ui lint`、`build`、`test` 通过；用真实浏览器走一遍：创建账号 → 发现模型 → 加入目录 → 编辑内置路由挂载策略 → 发请求 → 用量页看到 raw/shaped/reported → 清理预览。

### 阶段 8：文档清理与发布

- 删除或改写 `docs/`、`feature/`、`README.md` 中的 Kiro 内容（C12）；`docs/refactor-plan/`、`docs/plantree/`、`docs/kiro-*.md` 整体删除。
- README 按新系统重写：定位、配置、路由、账号、usage 整形、迁移。
- Docker 镜像名与 compose 文件改名。
- 打 `v1.0.0` tag。

| R5 调度、限制、优先级、映射 | 调度回归集通过；模型三层解析 table-driven 测试 |
| R6 全局一份、账号覆盖 | `AccountOverrides` 合并测试；`/accounts/{id}/effective` 显示来源层 |
| R7 整形基于路由 | 同一账号挂在两条不同策略的路由下，reported usage 不同；`/routes/{prefix}/effective` 显示策略来源 |
| R9 新分支 | `git log main..fork/claude-pool` 非空，`git log fork/claude-pool..main` 为空（只单向合入） |
| R10 协议透传 | 关闭全部路由功能时，假上游收到的请求体、请求头（除鉴权与 anthropic-version）与下游原始值逐字节一致；响应体除 usage 与 request-id 外逐字节一致 |
| C3 调度顺畅 | 压测：账号总并发 N，下游并发 N 时无排队；下游并发 2N 时队列推进、无 529；连接数 ≤ 500（C13） |
| C4 内部消化 | 假上游对某账号返回 429/500/网络错误，下游全部成功且 usage 记录显示换号 |
| C5 Redis 降级 | 关闭 Redis 后请求继续成功，日志显示进程内 lease |
| C6 兼容 | 官方会接受的请求全部透传成功；官方会拒绝的请求返回与官方一致的错误类型 |
| C7 注入无感知 | 保留的 4 项注入用真实 Claude CLI（临时 CLAUDE_CONFIG_DIR）验证模型不复述注入 |

真实 CLI 测试按 memory 约定：临时 `CLAUDE_CONFIG_DIR`，不改本机真实配置；压测复用共享编译目录、单跑、用完清理。
