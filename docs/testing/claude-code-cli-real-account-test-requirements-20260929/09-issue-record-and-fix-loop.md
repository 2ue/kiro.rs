# 09 问题记录与修复闭环

## 闭环流程

```
预检 → 执行用例 → 发现异常 → 判定归属 → 记录问题 → 修复 → 单测 → 回归（原用例 + 同组 + P0 冒烟）→ 关闭
                                  ↑                                               │
                                  └──────────────── 回归失败，重新打开 ───────────┘
```

1. **执行**：按 [README 执行顺序](README.md#执行顺序与配额预算) 跑用例，每条记录 PASS / FAIL / BLOCKED / N/A（附原因）。执行阶段不改代码。
2. **判定归属**，先排除非服务端问题：
   - 客户端行为（CLI 自身限制、关键词不改请求体等）→ 记为"客户端行为"，写进结论，不算缺陷；
   - 上游行为（Kiro 真实限制、免费 plan 不支持的模型、上游偶发 5xx）→ 记为"上游"，但要检查服务端的错误呈现、重试和账号状态处理是否正确，处理不当仍算服务端问题；
   - 测试环境问题（隔离没做好、打到别的端口、MCP server 写法不兼容）→ 修环境后重跑；
   - 服务端问题 → 进入记录。
3. **记录**：先在项目已有的问题清单中查找是否为已知问题；已知问题在原记录中补充本次复现证据，新问题按下文「问题记录模板」单独建一条记录（一个问题一条，不要合并），并在本轮执行报告中登记。
4. **修复**：每个问题单独修复、单独提交（提交信息引用问题编号）；修复必须附最小单测（红 → 绿），Cargo 命令按项目约定的方式执行。
5. **回归**：替换 19023 实例为修复后的二进制（记录 SHA-256），重跑：
   - 触发问题的原用例，至少 3 次（偶发类问题 5 次）；
   - 同组全部 P0/P1 用例；
   - README 中的 P0 冒烟集；
   - 修复涉及 converter / stream / payload guard / thinking 时，加跑 CC-T-21、CC-U-23、CC-L-01、CC-B-06。
6. **关闭**：回归全部通过后更新问题文档 `Status:`、"测试与验收"结果与索引；回归失败则重新打开并补充新的复现信息。

## 严重级别

| 级别 | 定义 | 示例 | 处理 |
| --- | --- | --- | --- |
| S0 / P0 | 主流程不可用或数据/上下文静默丢失 | 普通对话失败、工具调用必然 400、会话卡死、上下文被静默裁剪、凭据或内部信息泄漏 | 立即停止后续批次，先修 |
| S1 / P1 | 常用功能失败或结果错误，有绕过方式 | thinking 要求可见但无 thinking 块、MCP 某传输类型失败、压缩失败需手动处理、usage 长期为 0 | 本轮修复 |
| S2 / P2 | 边缘场景失败或体验问题 | 特定参数被忽略、错误文案不规范、count_tokens 偏差大 | 记录，排期修复 |
| S3 / P3 | 与官方协议有差异但无用户可见影响 | 字段顺序、非必需字段缺失 | 记录 |

## 执行报告模板

每轮执行生成一份报告（文件名建议 `claude-code-cli-real-account-<YYYYMMDD>.md`，放在项目的测试证据目录），包含：

- 环境：CLI 版本、kiro.rs 提交与二进制 SHA-256、实例 PID、运行配置关键项、账号数量与类型（不含凭据）、余额开始/结束值。
- 用例结果表：编号 | 模型 | 结果 | request id | 关联问题 | 备注。
- thinking 汇总表（见 [03 结果汇总要求](03-thinking.md#结果汇总要求)）。
- 新发现问题列表与已知问题复现情况。
- 未执行用例及原因（额度、环境、客户端不支持）。
- 清理确认：临时进程、tmux 会话、后台会话、抓包文件、隔离目录已清理；19023 实例状态。

## 验收标准

本轮测试视为通过需同时满足：

1. 所有 P0 用例在 sonnet-4.5 上 PASS，适用于 haiku 的 P0 用例在 haiku-4.5 上 PASS。
2. P1 用例通过率 ≥ 95%，未通过项都有问题记录且严重级别不高于 S2，或已归属为客户端/上游行为并有证据。
3. 无未关闭的 S0/S1 问题。
4. 全局判定规则（[README](README.md#全局判定规则)）零违反：无内部术语泄漏、无工具失配、无 usage 长期为 0、无无法解释的 5xx、无 panic。
5. 所有已修复问题完成回归并更新文档状态。
6. 测试后环境干净：无残留临时进程，账号 in-flight 为 0，未改动的运行配置与测试前一致，本机真实 `~/.claude` 未被修改。
