# 06 前端技术架构

## 1. 技术选型

版本号来自 2026-10 查询的 npm registry。开工时还要再核对一次，并锁定到精确版本。

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | React 19 | 原生支持 Actions 和 useOptimistic，适合启停这类乐观更新 |
| 构建 | Vite 8 + `@vitejs/plugin-react-swc` | 与现有工程一致，产物方便用 rust-embed 嵌入 |
| 样式 | Tailwind CSS 4 | CSS-first，token 写在 `@theme` 里，不再保留 tailwind.config |
| 组件 | shadcn/ui（`-b radix`） | 和现有 Radix 生态、用户的 UI 规范一致；组件源码放进仓库，可以直接改 |
| 路由 | TanStack Router（文件路由） | search params 有类型并用 zod 校验，正好满足"筛选写进 URL"；内置 `useBlocker` |
| 服务端状态 | TanStack Query 5 | 统一处理轮询、乐观更新和失效 |
| 表格 | TanStack Table + TanStack Virtual | 列显隐、Faceted 筛选、范围选择；明细数据量大，需要虚拟滚动 |
| 图表 | Recharts 3（shadcn Chart 封装） | 主题和 token 能打通；Tremor 已停更，只参考它的设计 |
| 表单 | react-hook-form + zod 4 | 配置草稿、导入向导的校验 |
| 客户端状态 | zustand | 只存 UI 偏好：侧栏、密度、主题、刷新频率、已保存视图 |
| 命令面板 | cmdk（shadcn Command） | Cmd+K |
| 通知 | sonner | toast 支持"撤销"按钮 |
| 国际化 | 第一阶段不引入 | 文案集中放在 `i18n/zh.ts`，以后需要时再接 i18next，不需要大改 |
| 测试 | Vitest + Testing Library + MSW；Playwright 冒烟 | 领域逻辑做单测，关键流程做 E2E |

不使用的方案：
- axios：改用原生 `fetch`，外面包一层 `apiClient`，可以少一个依赖。
- 全局 Redux：没有必要，服务端状态交给 TanStack Query，UI 偏好交给 zustand。
- Base UI：shadcn 新的默认选项，但和团队现有的 Radix 代码不一致。

依赖方向只能是 `routes → features → components/queries → api/domain`。用 ESLint 的 `import/no-restricted-paths` 强制，`features` 之间不允许互相引用。

## 3. 数据层约定

- **Query key 规范**：`[领域, 资源, 参数]`，例如 `['credentials','list',search]`，所有 key 由 `queries/keys.ts` 统一产出。
- **轮询由页面统一控制**：
  - 顶栏的 RefreshControl 写入 zustand，页面级 hook `usePollingInterval(tier)` 根据档位给出实际间隔。
  - 档位分三档：fast 对应运行态，normal 对应汇总，slow 对应额度。
  - 用户点"暂停"后全部停止。页面不可见时也停止（`refetchIntervalInBackground: false`）。
  - 组件内禁止硬编码 `refetchInterval`。
- **账号列表的数据组合**：
  - 一页数据由三部分合成：分页列表接口返回的基本字段，`/credentials/runtime` 批量返回的运行态，`account-info` 返回的额度快照。三者在 `queries/accounts.ts` 里用 `select` 合成为 `AccountRow`。
  - 每行不再单独发请求，也不再在行内挂 mutation hook。改成行通过 action 分发，统一使用 `useAccountActions()`。
- **Mutation 约定**：
  - 成功后按领域做失效（invalidate）。
  - 启停、优先级这类可恢复的修改用乐观更新加撤销。
  - 删除和清空不做乐观更新。
- **配置草稿**：
  - `useConfigDraft(section)` 保存草稿和打开时的 `baseVersion`。
  - 远端数据变化时，用 `config-diff.merge(base, remote, draft)` 做三方合并。有冲突的字段要标出来，由用户选择保留哪个。不允许静默覆盖草稿。
- **错误处理**：
  - `ApiError { status, code, message, raw }`。401 时触发 `auth:expired`，跳回登录页。
  - 其他错误通过 `upstream-error.ts` 翻译成可读文案。

## 4. 状态模型示例

```ts
// domain/credential-status.ts
export type PrimaryStatus =
  | 'disabled' | 'failing' | 'rateLimited' | 'cooling'
  | 'probation' | 'busy' | 'healthy' | 'unknown'

export interface CredentialStatusView {
  primary: PrimaryStatus
  secondary: PrimaryStatus[]      // hover 卡片中展示
  reason?: { code: string; label: string; action?: SuggestedAction }
  recoverAt?: number              // 冷却/限流/观察期的预计恢复时间(ms)
  schedulable: boolean            // 已禁用时必为 false（修复现状 bug）
}

/** 从后端原始字段推导唯一主状态；优先级见 05-视觉设计系统 §2 */
export function deriveCredentialStatus(raw: CredentialRaw, rt?: CredentialRuntime, now = Date.now()): CredentialStatusView
```

## 5. 质量门槛

- 开启 TypeScript `strict` 和 `noUncheckedIndexedAccess`；不允许 `any`，必要时写明原因。
- 业务层禁止使用原生 `<button>/<input>/<select>`，禁止色板类和任意字号，由 ESLint 自定义规则检查。
- 单文件不超过 400 行。
- 首屏 JS 小于 200KB（gzip），按路由拆分；图表和表格虚拟化相关代码按需加载。
- 账号列表在 2000 个账号时滚动不掉帧，用 Playwright 加 performance trace 验证。
