# 03 产品定位与信息架构

## 1. 定位

kiro-rs 控制台是 Kiro 账号池网关的运维控制台。用户是自建或小团队运营网关的管理员，通常一个人维护几十到几千个 Kiro 账号，外加少量外部上游池。

它不是终端用户的自助平台：没有注册、充值或用户分组。所以不照搬 new-api 那种"用户/令牌/充值"的信息架构。

## 2. 核心任务（按频率排序）

| # | 任务 | 用户关心的问题 | 现在需要跳转的页面 |
|---|---|---|---|
| T1 | 巡检 | 池子能不能扛？有没有在报错？ | 总览 5 个 Tab |
| T2 | 处置问题账号 | 哪些账号挂了？为什么？怎么批量处理？ | 账号页 + 校验页 |
| T3 | 补充账号 | 怎么最快把一批账号导进来并确认可用？ | 3 个导入入口 + 校验页 |
| T4 | 查请求 | 某个请求或会话为什么失败、慢、贵？ | 用量页弹窗 |
| T5 | 看成本与额度 | 额度什么时候耗尽或重置？外部池赚了还是亏了？ | 总览·费用 + 用量 + 风控 |
| T6 | 调参 | 调度、超时、外部池策略怎么改？改了什么？ | 运行页 + 外部池页（重复） |
| T7 | 管 Key 与审计 | 谁能调用？谁改了什么？ | 安全页 + 审计页 |

设计目标是每个任务都能在一个主页面内完成，必要的下钻通过 Sheet 完成。

## 3. 导航结构

```text
┌ 监控
│  ├ 总览                /overview          T1
│  └ 请求                /requests          T4（原"用量明细"）
├ 资源
│  ├ Kiro 账号           /accounts          T2 T3
│  ├ 外部池              /pools             T5 T6（含池级策略）
│  └ 代理                /proxies
├ 分析
│  ├ 成本与额度          /billing           T5（合并费用、外部池计费、风控）
│  └ 调度器              /scheduler         T1 T2（新增：调度可解释性）
└ 系统
   ├ 配置                /settings          T6（运行配置，按领域分组）
   ├ 模型                /models
   ├ 访问控制            /access            T7（Admin Key / 请求 Key）
   └ 审计日志            /audit             T7
```

与现状的映射：

| 现状 | 新位置 | 说明 |
|---|---|---|
| 总览 5 Tab | 总览（单页） + 成本与额度 + 调度器 | 总览只回答"现在是否健康" |
| 账号 + 校验 | Kiro 账号 | 校验合并为账号页的"体检"动作和导入向导中的预检步骤 |
| 外部池 + 运行·路由策略 | 外部池 → 策略 Tab | 外部池策略只保留这一个编辑入口 |
| 外部池风控 | 成本与额度 → 外部池风控 Tab | |
| 用量 | 请求 + 成本与额度 | 明细和聚合拆开 |
| 运行 | 配置 | 去掉外部池相关字段，按领域重新分组 |
| 安全 | 访问控制 | |

## 4. 全局元素

- **侧栏**：可折叠成图标栏，折叠状态会记住。分组标题下的条目带实时角标，比如"Kiro 账号 · 12 异常"。
- **顶栏**：面包屑、全局时间范围（今天 / 24h / 7d / 30d / 本月，与后端 `windows` 的口径一一对应）、刷新控制（暂停 / 10s / 30s / 60s）、命令面板入口、主题切换（亮 / 暗 / 跟随系统）。
- **命令面板（Cmd+K）**：
  - 页面跳转。
  - 搜索账号（按 ID、邮箱或标签）、请求（requestId）、外部池。
  - 执行动作，比如"刷新所有额度""导入账号""清除冷却"。
- **系统状态条**：位于侧栏底部，显示版本、usage 写入链路状态（正常 / 背压 / 丢弃），点击后打开系统健康 Sheet。

## 5. 一操作一入口

| 操作 | 唯一主入口 | 允许的快捷触发 |
|---|---|---|
| 负载均衡模式 | 配置 → 调度 | 调度器页只读展示，附"去修改"链接 |
| 刷新额度 | 账号页工具栏（全量或已选） | 详情 Sheet 内刷新单个；Cmd+K |
| 删除已禁用账号 | 账号页"按原因处置"菜单 | 无 |
| 同步价格 | 模型页 | 无 |
| 账号体检（原验活 / 复查） | 账号页批量动作"体检" | 导入向导预检复用同一个能力 |
| 外部池策略 | 外部池 → 策略 | 无 |

快捷入口必须调用同一个 action hook，见 [06](06-前端技术架构.md)。
