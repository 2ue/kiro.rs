# 04 交互与页面设计

## 1. 统一交互范式

| 范式 | 规则 |
|---|---|
| 列表 + 详情 Sheet | 点击列表中的一行，右侧打开 Sheet（宽 560 到 720px），URL 带上 `?id=`，可以直接分享，刷新后保持打开 |
| 筛选写进 URL | 筛选、排序、分页、视图都存在 search params 里，用 zod 校验；常用组合可以保存为"视图"，存在 localStorage |
| 批量操作栏 | 勾选行后，底部浮出操作栏，显示"已选 N 项"；支持 Shift 范围选择，也支持"选中全部 N 条筛选结果"（分页之外的数据） |
| 配置草稿 | 修改后进入脏状态，顶部出现粘性保存条，显示"N 项修改 · 查看差异 · 放弃 · 保存"；保存前展示字段级 diff；切换路由时由 `useBlocker` 拦截；服务端数据变化不会覆盖草稿，只提示"远端已更新" |
| 危险操作 | 禁用、删除、清空这类操作统一用 AlertDialog；批量删除需要输入数量确认；可恢复的操作（启停）用乐观更新，并在 toast 里提供"撤销" |
| 未知 ≠ 0 | 没有快照时显示"—"和"未查询"，同时提示快照时间；快照超过 30 分钟标为"可能过期" |
| 错误翻译 | 上游错误统一映射为"中文标题 + 建议动作 + 原文折叠" |
| 弹层选择 | 聚焦表单用 Dialog；对象详情和配置用 Sheet；快速选择用 Popover；行操作用 DropdownMenu |

## 2. 页面设计

### 2.1 总览 `/overview`

只回答一个问题：现在是否健康。

```text
┌────────────────────────────────────────────────────────────────────┐
│ 容量水位  ████████████░░░░  在途 42 / 上限 64 · 排队 0               │
│ 账号池    ▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇ (Tracker：可调度/冷却/在用/异常/禁用) │
├──────────┬──────────┬──────────┬──────────┬──────────┐
│ 请求数    │ 错误率    │ P95 延迟  │ 缓存命中  │ 费用      │  ← KPI + sparkline + 环比
├──────────┴──────────┴──────────┴──────────┴──────────┤
│ 请求趋势（成功/错误 堆叠） 24h/7d                       │ 需要关注（行动队列）     │
│                                                       │ · 8 个账号 InvalidRefresh │
│                                                       │ · 3 个账号 2h 内额度重置  │
│                                                       │ · 外部池 A 冷却 4m 后恢复 │
│                                                       │ · usage 写入背压          │
├───────────────────────────────────────────────────────┴──────────────┤
│ Top 模型 │ Top 账号 │ Top 错误（标注"仅前 N / 共 M"）                    │
└────────────────────────────────────────────────────────────────────┘
```

- 每条行动队列项都可以点击，跳转到对应的筛选视图，比如 `/accounts?reason=InvalidRefreshToken`。
- 数据源：`/credentials/summary`、`/usage-dashboard/windows|series|top`、`/external-pools/status`、`/usage-writer-stats`。

### 2.2 Kiro 账号 `/accounts`

默认使用表格视图，可以切换到卡片视图。

- **顶部状态分段**：全部 / 可调度 / 冷却 / 限流 / 异常 / 已禁用，每段带计数。点击已禁用后，会展开禁用原因的二级分段（9 种原因翻译成中文）。
- **工具栏**：搜索、Faceted 筛选（认证方式、订阅、Region、标签、代理、模型）、列显隐、密度切换、导入（主按钮）、刷新额度。
- **表格列**：
  - 账号：邮箱 / ID / 标签
  - 状态：统一状态徽章，hover 显示原因和恢复倒计时
  - 订阅
  - 额度：分色进度条加"重置于 3d"
  - 调度：评分和 5m 选中次数的 mini bar
  - 在途 / 并发
  - 错误率
  - 代理来源
  - 最近使用
- **批量动作**：启用、禁用、体检、刷新额度、改优先级/并发/RPM、改标签、绑定代理、删除。
- **按原因处置菜单**：每种禁用原因对应一个推荐动作。

  | 原因 | 推荐动作 |
  |---|---|
  | InvalidRefreshToken | 批量删除 / 重新认证 |
  | QuotaExceeded | 等待重置（列出时间） |
  | TooManyFailures | 重置失败计数并体检 |

- **详情 Sheet**（行内不再嵌入弹窗），分 Tab：
  1. 概览：状态解释、额度、超额、调度指标
  2. 设置：分为"常用"和"高级"两部分，用草稿模式编辑
  3. 模型：支持的模型，可同步或探测
  4. 诊断：运行态，以及该账号最近的请求（复用请求表组件）
  5. 认证：刷新 Token、修改认证信息

#### 导入向导（Dialog，3 步）

替代原来的添加账号、批量导入和 KAM 导入三个入口。

1. **来源**：Tab 切换 JSON/文本粘贴、文件拖拽、KAM 导出、单个手动填写，自动识别格式。
2. **预检**：调用 `/credential-validation/external`，逐行显示可用 / 重复 / 无效 / 订阅档位，可以剔除不需要的行。
3. **默认参数**：只展开常用的 4 项（优先级、并发、标签、代理），其余折叠在"高级"里。最后通过 `POST /credentials/import` 一次性提交，然后展示结果汇总。

### 2.3 外部池 `/pools`

- **列表 Tab**：
  - 卡片栅格，每张卡展示：状态（可派发，或不可派发及原因）、在途/并发、错误率、TTFT、退避层级、恢复进度、今日成本与利润。
  - 行动作：测试、启停、清除冷却、清除自动禁用。
- **策略 Tab**：外部池路由策略唯一的编辑入口，使用草稿模式。字段按以下分组：何时兜底、何时直连、冷却与自动禁用、计费投影。
- 详情 Sheet 分为概览、模型、测试、最近请求。

### 2.4 代理 `/proxies`

- 表格列：名称、类型、地址（脱敏）、启用状态、绑定账号数、最近测试结果和延迟。
- 支持批量导入和测试。
- 详情 Sheet 列出绑定的账号，可以跳转。

### 2.5 请求 `/requests`

- 表格使用虚拟滚动和游标分页（每次加载更多 100 条）。
- 默认显示 8 列：时间、状态、模型、路由（本地/外部池）、账号/池、tokens、费用、TTFT/耗时。
- 其余列可以通过列显隐打开。
- 筛选包括：时间（跟随全局）、状态、模型、路由、账号、外部池、请求 Key、stream、会话 ID、最小 cache read、最小首 token 延迟。
- 详情 Sheet 内容：
  - 时间线（尝试链：账号 A 失败 → 账号 B 成功）
  - token 与缓存拆分
  - 费用口径（原价 / 估算 / 外部池计费）
  - payload guard 报告
  - 错误详情
  - 同会话的其他请求
- 清理操作放到"更多"菜单，使用原有的异步清理任务，并显示进度。

### 2.6 成本与额度 `/billing`

分为 3 个 Tab：

- **概览**：
  - 费用趋势，按模型、按账号、按端点拆分。
  - 页面上直接写明口径："估算费用按模型价格目录计算，不等于上游实际扣费"。
  - 缓存读写占比。
- **额度**：
  - 账号额度队列：即将耗尽（使用率超过 80%）、即将重置（7 天内）、超额中。
  - 积分汇总，分启用和禁用两组。
  - 快照过期提示，附"刷新"按钮。
- **外部池**：盈亏表，列为池、请求数、raw 成本、shaped 成本、reported、billable、利润、低于成本的次数。另有风控样本列表（原风控页内容）。

### 2.7 调度器 `/scheduler`（新增）

- 显示当前负载均衡模式（只读）。
- 候选排行：按 `schedulerScore` 排序，展示选择压力、10s/60s/5m 选中次数、在途、`inProbation` 剩余时间。
- 选中分布：Top 20 账号的 5 分钟选中占比，用来判断流量是否集中。
- 不可调度清单：按原因分组，显示恢复时间，点击可跳转到账号。

### 2.8 配置 `/settings`

- 左侧是领域导航（重新划分后约 7 组）：调度与冷却、重试与超时、流式、Payload 防护、Prompt 缓存、模型映射与兼容、其他。
- 每组只默认展示常用字段，"高级"折叠。字段旁边标出"已修改"的状态点，并提供"恢复默认"。
- 支持字段搜索，在 Cmd+K 里也能直接搜到配置项。
- 提供 JSON 模式，可以对整份配置做查看、编辑和对比 diff。
- 保存方式：第一阶段仍然 PUT 整份配置，但必须基于最新的服务端版本合并草稿，见 [07](07-后端集成与迁移计划.md)。

### 2.9 模型 `/models`

- 能力和价格合为一张表，同一行展示 context、能力标签、输入/输出/缓存价格、来源（同步 / 手工）。
- 支持行内编辑，提交前展示 diff。
- 同步按钮放在这里，作为唯一入口。

### 2.10 访问控制 `/access`

- Admin Key 轮换：生成后只显示一次，旧 Key 立即失效，操作前需要二次确认。
- 请求 Key 表格：名称、前缀脱敏、准入规则、最近使用、今日用量（链接到请求页的筛选结果）。
- 接入示例：curl、Claude Code 的 `ANTHROPIC_BASE_URL`，Key 用占位符代替。

### 2.11 审计 `/audit`

- 用时间线展示，详情放在 Sheet。
- 只有在后端支持筛选之后才提供筛选。在那之前只做分页，避免出现"只筛选了当前页"的误导。

### 2.12 登录

- 输入 Admin Key 后，调用 `/system/version` 校验。
- 默认把 Key 存在 sessionStorage，勾选"在此设备记住"时才写入 localStorage，并给出风险提示。
- 401 时统一跳回登录页，登录成功后回到原来的页面。

## 3. 移动端

- 768px 以下侧栏收进 Sheet。
- 表格切换为卡片列表，只展示主列、状态和操作。
- 只读巡检（总览、账号状态、请求）完整可用；配置类页面提示"建议在桌面端编辑"，但仍然可以操作。
