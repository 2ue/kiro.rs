# 管理后台 UI 重构设计方案（console）

日期：2026-10-01
范围：管理后台前端整体重做，放到新目录 `console/`，挂载在 `/console`。现有 `ui/`（`/ui`）和 `admin-ui/`（`/admin`）保持原样运行，等新版验收后再下线。
后端：沿用当前 Rust 管理 API（`/api/admin`）。第一阶段不改接口，少量增强接口单独列出，见 [07](07-后端集成与迁移计划.md)。

## 核心结论

1. 功能不缺，问题在组织方式。`ui/` 已经覆盖了后端几乎全部能力，但信息架构是按"数据表"划分的，没有按"运维任务"划分。结果是同一个操作有 3 到 4 个入口，外部池策略在两个页面都能编辑并且会互相覆盖，账号状态直接显示后端的原始枚举。
2. 系统定位是"Kiro 账号池网关的运维控制台"，不是通用 SaaS 后台。用户每天要回答的问题有四个：池子还能不能扛、哪些账号出了什么问题、钱和额度花在哪、调度为什么这样选。新 UI 的一级导航和首页都围绕这四个问题组织。
3. 差异化重点有三个，同类 Kiro 项目都没有做好：
   - 调度可解释：每个账号、每个外部池都说明"为什么现在不接流量、什么时候恢复"。
   - 额度生命周期：已用和总量、重置倒计时、超额状态、快照是否过期。
   - 外部池盈亏：成本、上报价和利润集中在一处展示。
4. 交互骨架：账号和请求统一用"列表 + 右侧详情 Sheet"，筛选条件写进 URL，配置统一走"草稿 → diff 预览 → 保存"，再加上 Cmd+K 命令面板、全局时间范围和用户可控的刷新频率。
5. 技术栈：React 19 + Vite + Tailwind v4 + shadcn/ui（Radix）+ TanStack Router/Query/Table/Virtual + Recharts + react-hook-form/zod。新目录从零搭建，不复用 `ui/` 的页面代码，只迁移经过核对的类型定义和 API 封装。

## 需要先确认的事项

- `docs/refactor-plan/07-前端重构方案.md` 写的是"Go 负责后端"，但仓库实际是 Rust（axum + rust-embed）。本方案按现有 Rust API 设计。如果后端迁移到 Go 的计划还在推进，需要先冻结 API contract，也就是 [06](06-前端技术架构.md) 里的 `api/` 层。
- 新目录名暂定 `console/`，挂载在 `/console`。如果更希望新版直接替换 `/ui`，见 [07](07-后端集成与迁移计划.md) 的切换方案。
