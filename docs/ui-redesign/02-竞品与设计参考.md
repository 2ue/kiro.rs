# 02 竞品与设计参考

调研时间为 2026-10。【确认】表示来自项目 README、官方文档或 npm；【推测】表示基于公开描述的推断。

## 1. Kiro 相关项目

| 项目 | 管理 UI 形态 | 值得借鉴 | 不借鉴 |
|---|---|---|---|
| [hank9999/kiro.rs](https://github.com/hank9999/kiro.rs)（上游原型） | 一张凭据表 | 无 | 信息密度低 |
| [dwgx/KiroStudio](https://github.com/dwgx/KiroStudio) | Overview / Credentials / Usage / Settings 四页 | 浏览器内完成 Social/IdC 登录并自动入库【确认】；RPM 软限制按权重降级；按客户端设备分析用量 | OTA 升级（不适合我们的部署方式） |
| [tanu360/kiro-reverse-api](https://github.com/tanu360/kiro-reverse-api) | Live Monitor / Pool / Request Log / Playground / Backups | 账号额度和代理侧用量分开展示；流量热力图；日志中 Key 脱敏；管理员登录限流【确认】 | 无 |
| [Quorinex/Kiro-Go](https://github.com/Quorinex/Kiro-Go) | `/admin` 单页 | 7 种凭据导入方式集中在一个入口；代理改动即时生效 | 无 |
| [chaogei/Kiro-account-manager](https://github.com/chaogei/Kiro-account-manager)（Electron） | 网格/列表双视图、分组 Tab | 额度进度条四档配色，超额时显示斜纹溢出段；批量检查后可一键重置封禁；诊断页；多格式导入加分组【确认】 | 机器码伪装、批量注册（违反 ToS） |
| [jwadow/kiro-gateway](https://github.com/jwadow/kiro-gateway) | 无 UI | 429/402 自动换号，隔离后定期复检 | 无 |
| [OmniRoute 讨论](https://github.com/diegosouzapw/OmniRoute/discussions/5001) | 无 | 基于 `GetUsageLimits` 展示"已用/总量 + 重置日期"【确认】 | 无 |

结论：Kiro 服务端项目的后台普遍很初级。账号健康和额度可视化做得最好的是桌面端管理器，但它不涉及调度和计费。

## 2. AI 网关后台

| 项目 | 值得借鉴 | 被诟病或要避免 |
|---|---|---|
| [new-api](https://github.com/QuantumNous/new-api) | 渠道表格和卡片双视图；Sankey 图展示 token 流向；React 19 + TanStack + Tailwind 4 | 倍率公式难懂；令牌额度和账户额度容易混淆；上游错误原样展示，看不懂【确认 FAQ】 |
| [claude-relay-service](https://github.com/Wei-Shaw/claude-relay-service) | 账号不可调度时说明原因：错误类型、状态码、冷却剩余时间、预计恢复时间，并提供"重置状态"按钮【确认】 | 历史上出现过管理员认证绕过漏洞 |
| [sub2api](https://github.com/Wei-Shaw/sub2api) | 每种错误码都有明确的调度语义；在拿到上游数据之前，额度显示为 unknown，不显示 0 | 无 |

| [Helicone](https://docs.helicone.ai) | 会话树视图；基于错误率、成本、延迟的告警 | 无 |

## 3. 设计语言参考

- [satnaing/shadcn-admin](https://github.com/satnaing/shadcn-admin)：Vite + TanStack Router + shadcn 骨架，有可折叠侧栏、Cmd+K、明暗主题，可以直接作为外壳参考。
- [shadcn/ui](https://ui.shadcn.com)：Blocks 里有 dashboard、sidebar、data-table、charts。2026-07 起新项目默认使用 Base UI，加 `-b radix` 参数可保留 Radix【确认】。我们选 Radix，与现有代码和用户规范保持一致。
- [Tremor](https://tremor.so)：被 Vercel 收购后改为 copy-paste 模式，npm 包已经停更。只参考它的 KPI 卡片和 Tracker（状态条）组件。
- Linear、Vercel、Supabase Studio、Grafana【推测】：
  - 左侧可折叠侧栏；顶部是面包屑、全局时间范围和刷新控制。
  - 详情用右侧 Sheet 打开，不跳转页面。
  - 筛选条件写进 URL，选中行后在底部浮出批量操作栏。
  - 数字使用 tabular-nums 并右对齐；中性灰底配单一品牌色。
  - 所有图表共享同一个时间范围，hover 时十字线联动。

## 4. 提炼出的设计原则

1. 每个状态都要说明原因和恢复时间。参考 claude-relay-service。
2. 计费口径直接在页面上解释。new-api 的反例说明，口径说不清会带来大量咨询。
3. 不知道就显示"未知"，不显示 0。参考 sub2api 对额度快照的处理。
4. 配置变更必须先看 diff。参考 CPA。
5. 详情放在 Sheet 里，列表的上下文不丢。参考 OpenRouter、Linear。
6. 一个操作只有一个主入口，其他位置可以快捷触发，但必须调用同一个 action。
