## 2. 未完成

### 2.1 Mock 数据模式（进行中）

目标：每个页面都有数据，用于演示和视觉走查；不写入任何真实数据库。

现状：
- 已有 `console/src/mocks/rand.ts`（固定种子的伪随机数）
- 已有 `console/src/mocks/fixtures/`：运行配置、模型能力、模型价格的快照（来自本地后端，已去掉代理凭据和错误信息）
- 尚未接入：数据集生成、请求拦截、启动脚本

计划：
1. **启动方式**：`pnpm dev:mock`，即 `vite --mode mock --port 9028`。`import.meta.env.MODE === 'mock'` 时，在 `main.tsx` 中动态加载 mock 模块。正常构建会通过 tree-shaking 排除这些代码，用 `pnpm size` 确认首屏体积不变。
2. **拦截方式**：替换 `api/client.ts` 底层的 `fetch`，只拦截 `/api/admin/*`，不引入 MSW，以免增加依赖和 Service Worker。登录接口直接放行，任意 Key 都能登录。
3. **数据集**（`mocks/data/*.ts`，固定种子，数据之间相互一致）：
   - 账号 120 个：覆盖 Social / IdC / 外部 IdP / API Key；订阅分 Free / Pro / Pro+ / Power；9 种禁用原因各至少 1 个；冷却、限流、并发满、观察期、预热、异常各若干；额度使用率分布在 0~120%；重置时间分布在 1~30 天
   - 外部池 5 个：可派发、冷却中、自动禁用、降级观察、已停用各 1 个；附带质量指标和计费数据
   - 代理 8 个：含已停用、绑定数为 0 的情况
   - 请求记录 2000 条：覆盖成功和 4 类错误、本地与外部池、流式与非流式；包含多次尝试链、外部池计费、payload guard 报告
   - 用量看板：今天 / 24h / 昨天 / 7d / 30d / 本月 6 个时间窗口，24 小时和 7 天的序列，Top 榜单（带截断标记），外部池风控样本
   - 审计 150 条（含失败记录），请求 Key 3 个，写入链路状态（带背压计数）
4. **写操作**：启停、改设置、删除、导入、保存配置都在内存中生效，刷新页面后恢复初始状态。导入会模拟 1~2 秒延迟和约 30% 的失败率，用于演示逐项进度。
5. **验收**：逐页走查（亮色、暗色、手机宽度）。每个页面都没有空状态，控制台没有报错。
6. **测试**：E2E 冒烟改为复用这套 mock 数据，替换掉目前手写的 `e2e/fixtures.mjs`，避免维护两份数据。
