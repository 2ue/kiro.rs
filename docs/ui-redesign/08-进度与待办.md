# 08 进度与待办：运维控制台（console）

更新日期：2026-10-02

本文记录"运维控制台"前端重构的完成情况、未完成事项和执行计划，不依赖任何对话上下文也能读懂。设计依据见同目录的 README.md 和 01～07 号文档。

## 0. 名词与位置

| 名词 | 含义 |
|---|---|
| 运维控制台、console | 本次新建的管理后台前端，源码在仓库根目录下的 `console/`，由 Rust 后端挂载在 URL 路径 `/console`。 |
| 现行 UI | 仓库中已有的 `ui/` 目录，挂载在 `/ui`。本次重构没有修改它。 |
| 旧版 UI | 仓库中已有的 `admin-ui/` 目录，挂载在 `/admin`。本次重构没有修改它。 |
| 管理 API | Rust 后端提供的 `/api/admin/*` 接口，三套前端共用。本次重构没有新增或修改任何管理 API。 |
| 功能分支 | Git 分支 `feat/console-ui`，所有改动都在这里，已推送到远端 `origin`（`git@github.com:2ue/kiro.rs.git`）。 |
| 基线 | 功能分支从 `main` 的提交 `2a45a54`（版本 0.0.183）切出。 |

本分支在 `console/` 之外只改了这些文件，作用都是让后端托管 `/console`，并把它纳入构建与 CI：
- `src/admin_ui/router.rs`、`src/admin_ui/mod.rs`、`src/main.rs`：后端在 `/console` 挂载 `console/dist`；release 构建会把它嵌入二进制。
- `Dockerfile`、`.dockerignore`、`.gitignore`、`.github/workflows/build.yaml`：构建、检查和忽略规则。
- `scripts/dev-ui.sh`：新增 `console` 参数，`bash scripts/dev-ui.sh console` 会在 9027 端口启动控制台开发服务器。
- `docs/ui-redesign/`：设计文档和本文。

## 2. 未完成事项与计划

### 2.1 Mock 数据模式（已开始，尚未接入）

**目标：** 在不连接真实后端数据库的情况下，让控制台每个页面都显示有代表性的数据，用于演示和视觉走查。

**已有：**
- `console/src/mocks/rand.ts`：固定种子的伪随机数生成器，保证每次打开看到的数据都一样。
- `console/src/mocks/fixtures/`：从本地后端导出的三份快照（运行配置、模型能力目录、模型价格目录）。运行配置中的代理地址、用户名和密码已删除，所有快照都不含密钥。

**还没做：** 数据集生成、请求拦截、启动命令。这些文件目前都没有被代码引用，不影响现有功能。

**计划：**
1. **启动方式**：在 `console/package.json` 中新增命令 `pnpm dev:mock`，等价于 `vite --mode mock --port 9028`。只有在 `import.meta.env.MODE === 'mock'` 时，`src/main.tsx` 才动态加载 mock 模块。生产构建依靠 tree-shaking 排除这些代码，并用 `pnpm size` 确认首屏体积没有变化。
2. **拦截方式**：替换 `src/api/client.ts` 里使用的 `fetch`，只拦截 `/api/admin/*`。不引入 MSW，避免增加依赖和 Service Worker。登录接口直接放行，输入任意 Key 都能登录。
3. **数据集**放在 `src/mocks/data/*.ts`，使用固定种子，各数据集之间互相一致（例如请求记录里引用的账号 ID 在账号列表中确实存在）：
   - 账号 120 个：覆盖 Social、IdC、外部 IdP、API Key 四种认证方式；订阅覆盖 Free、Pro、Pro+、Power；后端定义的 9 种禁用原因每种至少 1 个；冷却、限流、并发已满、观察期、预热、异常这几种状态各若干个；额度使用率分布在 0%～120%；重置时间分布在 1～30 天后。
   - 外部池 5 个：可派发、冷却中、自动禁用、降级观察、已停用各 1 个，并带有质量指标和计费数据。
   - 代理资源 8 个：包括已停用的、没有绑定任何账号的。
   - 请求记录 2000 条：覆盖成功和 4 类错误、本地账号和外部池两种路由、流式和非流式；部分记录带多次尝试链、外部池计费和请求体保护报告。
   - 用量看板：今天、最近 24 小时、昨天、最近 7 天、最近 30 天、本月共 6 个时间窗口；24 小时按小时的序列和 7 天按天的序列；Top 榜单，包括被截断的情况；外部池风控样本。
   - 其他：审计日志 150 条（含失败记录）、请求 API Key 3 个、用量写入链路状态（含背压计数）。
4. **写操作**：启用/禁用、修改设置、删除、导入、保存配置都只改内存数据，刷新页面后恢复初始状态。导入每个账号模拟 1～2 秒延迟和约 30% 的失败率，用来演示逐个账号的导入进度。
5. **验收**：在亮色、暗色、手机宽度（390 px）三种条件下逐页查看。每个页面都有数据（没有空状态），浏览器控制台没有错误。
6. **测试复用**：E2E 冒烟测试改为使用这套 mock 数据，删除目前手写的 `console/e2e/fixtures.mjs`，避免维护两份数据。

### 2.2 同步 main 分支的新改动

**原因：** 功能分支切出后，main 又合入了两个提交，新增了运行配置字段。控制台目前还读不到、也改不了这些字段：
- `4cd40b1`：新的缓存策略 `stable_segment_cache`。新增字段 `CachePolicyConfig.stableSegmentCache` 和 `CacheRoutePolicyPatch.stableSegment`。
- `c7f9edb`：语言提示词改为可选，并跟随客户端语言。新增字段 `languageConstraintPrompt`、`taskQualityPrompt`，以及只读字段 `promptSteeringDefaults`（后端内置的默认提示词文本）。

控制台保存运行配置时，会先读取服务端最新的完整配置，再把用户改过的字段合并进去，所以不认识的字段会原样保留，不会被清掉。但在控制台里没法编辑这些字段。

**计划：**
1. 在功能分支上执行 `git merge main`。冲突只可能出现在 `ui/` 和后端，处理时以 main 为准。
2. 在 `console/src/api/types/` 中补上述字段的类型。
3. 运行配置页：
   - 在「Prompt 缓存」分组中加入 stable segment 策略的说明和入口。按路径绑定策略目前在「高级 JSON」中编辑，需要确认 `cachePolicy` 的 JSON 编辑器能完整读写新字段。
   - 在「提示词引导」分组中加入 `languageConstraintPrompt`、`taskQualityPrompt` 两个文本字段，以及读取 `promptSteeringDefaults` 的"恢复默认"按钮。
4. 重新导出 `console/src/mocks/fixtures/runtime-config.json`，并重新执行 1.2 节中的所有检查。

### 2.4 已知限制（需要后端配合，暂不处理）

- 账号页按"禁用原因"筛选只作用于当前页。要筛选全部账号，需要 `GET /api/admin/credentials-paged` 支持 `disabledReason` 参数。
- 审计日志页只能翻页，不能筛选。需要 `GET /api/admin/audit-logs` 支持按操作人、动作、对象类型、成败和时间筛选。
- 保存运行配置仍然是用 `PUT /api/admin/config/runtime` 提交整份配置。前端已经用三方合并来避免覆盖别人的修改；要彻底解决，需要后端提供带版本号的 `PATCH`。
- 账号导入时，API Key 类型的账号即使上游预检失败也能添加成功，因为后端添加时不会再校验。控制台默认开启"验活"，验活失败会自动删除该账号，以此兜底。
- 没有构建完整的 Docker 镜像（只验证了前端构建阶段），也没有用真实账号做长时间回归测试。

## 4. 从零接手本分支

```bash
git fetch origin
git switch feat/console-ui
cd console
pnpm install --frozen-lockfile   # 需要 pnpm 11；CI 和 Docker 使用 11.11.0
pnpm dev                          # http://127.0.0.1:9027/console/ ，/api 会代理到 127.0.0.1:9022
```

后端仍然按仓库 README 启动。debug 构建下，访问 `http://<后端地址>/console` 会自动跳转到 9027 端口的开发服务器。
