# 调度 Redis 降级与 CPU 放大防护推荐配置

日期：2026-07-31

适用版本：`v0.0.124` 及之后

## 目的

这份文档用于把“调度 Redis 抖动后 CPU 被打满”的修复建议映射到后台页面上的配置文案。

文档分两类：

- 页面可配置项：直接按页面上的中文文案填写。
- 页面不可配置项：不是让你到页面里配置，而是说明它现在由代码、启动部署或调用方控制。

注意：代码里的默认值只影响新初始化或缺失字段。现网数据库里已经存在的运行态配置不会被默认值自动覆盖。现网要生效，需要在页面保存运行配置，或通过运行态配置接口/数据库更新。

## 先说结论

这次现网要优先手动改的是“页面可配置项”，也就是：

- 运行配置 -> 请求容量
- 外部池 -> 外部账号策略

页面不可配置项不要在后台页面里找，也不是本轮必须逐项修改。它们的状态如下：

| 类别 | 是否需要你在页面配置 | 当前状态 | 是否需要后续改 |
|---|---|---|---|
| 调度 Redis 降级 fallback 判断 | 不需要 | `v0.0.124` 已通过代码修复 | 本轮不用再改 |
| 新初始化默认值 | 不需要 | `v0.0.124` 已写入代码默认值 | 只影响新初始化，不覆盖现网已有运行态 |
| 调度 Redis 热路径超时 | 页面不能配 | 代码固定保护值 | 本轮不建议改，先观察 |
| 调度 Redis 连续失败保护 | 页面不能配 | 代码固定保护逻辑 | 本轮不建议改，先观察 |
| 独立观测 Redis | 页面不能配 | 启动部署配置项 | 可选后续部署优化 |
| 客户端重试间隔和次数 | 服务端页面不能配 | 调用方控制 | 需要调用方配合时再改 |

## 页面可配置项

### 一、运行配置 -> 请求容量

路径：新版后台左侧进入“运行”，页面标题“运行配置”，选择分组“请求容量”。

| 页面文案 | 推荐值 | 说明 |
|---|---:|---|
| 每实例 · 每 Key RPM | 300 | 每个实例分别限制每个已认证请求 Key 的进入速率；多实例总量约等于实例数倍。 |
| 每实例 · 每 Key 并发 | 32 | 每个实例内，同一请求 Key 同时持有的响应体数量上限。 |
| 每实例 · 每 Key 队列 | 64 | 同一请求 Key 并发占满后，入口层最多允许等待的请求数。 |
| 每实例 · 每 Key 等待 | 1000 毫秒 | 入口层等待并发名额的最长时间；建议保持 1 秒级。 |
| 单账号每分钟请求上限 | 100 | 每个本地账号一分钟最多承接多少请求；避免单账号过载。 |
| 单账号最大并发 | 30 | 每个本地账号同一时间最多处理多少请求。 |
| 全局最大并发 | 512 | 所有本地账号合计并发上限；接近 17 个账号 x 30 并发的真实容量。 |
| 最大排队请求数 | 30 | 本地账号忙不过来时，最多允许多少请求进入本地调度等待队列。 |
| 单请求最长排队等待 | 5 秒 | 单个请求最多等本地账号空闲多久；不要回到 300 秒。 |

推荐原则：

- 入口层先限流，避免请求全部进入本地调度器。
- 本地调度等待队列必须短，等待时间必须短。
- 全局最大并发不要设置成远大于真实账号容量的数值。

### 二、外部池 -> 外部账号策略 -> 启用控制

路径：新版后台左侧进入“外部池”，卡片标题“外部账号策略”。

| 页面文案 | 推荐值 | 说明 |
|---|---|---|
| 启用外部账号 | 开启 | 不开启时，任何外部账号兜底都不会生效。 |

### 三、外部池 -> 外部账号策略 -> 触发条件 -> 本地优先

| 页面文案 | 推荐值 | 说明 |
|---|---|---|
| 本地容量预检 | 开启 | 请求先判断本地账号池是否还有可用容量。 |
| 容量不足时使用外部账号 | 开启 | 本地容量满时允许转外部账号。 |
| 调度 Redis 降级时使用外部账号 | 开启 | 本次事故修复的关键开关。调度 Redis 不可信时，不再继续死等本地池。 |
| 没有可用账号时使用外部账号 | 开启 | 本地没有可调度账号时允许转外部账号。 |
| 本地临时错误过多时使用外部账号 | 开启 | 本地冷却、瞬态失败过多时允许转外部账号。 |
| 模型不支持时使用外部账号 | 开启 | 本地账号不支持请求模型时允许转外部账号。 |

最关键的四项：

| 页面文案 | 推荐值 |
|---|---|
| 调度 Redis 降级时使用外部账号 | 开启 |
| 容量不足时使用外部账号 | 开启 |
| 没有可用账号时使用外部账号 | 开启 |
| 本地临时错误过多时使用外部账号 | 开启 |

### 四、外部池 -> 外部账号策略 -> 触发条件 -> 显式直连

| 页面文案 | 推荐值 | 说明 |
|---|---|---|
| 启用显式直连 | 关闭 | 推荐本地优先、异常兜底，不推荐所有请求默认跳过本地账号。 |
| 记录本地保护原因 | 可不改 | 主要在显式直连开启时用于记录原因。 |

### 五、外部池 -> 外部账号策略 -> 触发条件 -> 本地保护统计

这组配置是本地账号池的整池风险统计和暂停保护。它不是 Redis scheduler breaker，但能在短窗口内多个账号出现本地风险时，避免继续探测剩余本地账号。

| 页面文案 | 推荐值 | 说明 |
|---|---:|---|
| 启用本地保护统计 | 开启 | 多个账号连续触发本地池风险时，短暂停止继续探测本地池。 |
| 统计窗口 | 60 秒 | 统计本地池风险事件的短窗口。 |
| 失败阈值 | 3 次 | 窗口内达到该失败次数后打开本地保护。 |
| 涉及账号 | 2 个 | 至少涉及多个账号才打开，避免单账号噪声误伤整池。 |
| 暂停时长 | 30 秒 | 保护打开后短暂停止探测本地池，避免整池被连续打穿。 |

### 六、外部池 -> 外部账号策略 -> 调度策略 -> 容量与排队

#### 方案 A：更稳的止血配置

这组配置最能避免外部池也形成排队放大。

| 页面文案 | 推荐值 | 说明 |
|---|---|---|
| 满并发处理 | 立即失败 | 外部账号满并发时不排队，快速失败。 |
| 全局并发上限 | 512 | 限制所有外部账号合计并发。 |
| 最大重试 | 1 | 避免外部池失败后多次重试放大流量。 |

选择“立即失败”后，“外部池排队上限”和“最大等待”可能会灰掉或不生效，这是正常的。

#### 方案 B：兼顾成功率的短等待配置

如果希望外部账号满并发时短暂等一下，用这组配置。

| 页面文案 | 推荐值 | 说明 |
|---|---:|---|
| 满并发处理 | 等待容量 | 外部账号满并发时进入短等待。 |
| 全局并发上限 | 512 | 限制所有外部账号合计并发。 |
| 外部池排队上限 | 10 | 外部池最多排队 10 个请求。 |
| 最大等待 | 5 秒 | 外部池等待容量最多 5 秒。 |
| 最大重试 | 1 | 不允许多次重试放大。 |

不要再使用以下组合：

| 页面文案 | 不建议值 | 原因 |
|---|---:|---|
| 外部池排队上限 | 100 | 容易堆积等待请求。 |
| 最大等待 | 300 秒 | 会形成长时间挂起和周期性唤醒。 |
| 最大重试 | 6 | 失败时会明显放大请求量。 |

### 七、外部池 -> 外部账号策略 -> 调度策略 -> 外部账号失败后回本地

| 页面文案 | 推荐值 | 说明 |
|---|---|---|
| 启用回本地 | 开启 | 外部账号失败后允许有限回本地抢救。 |
| 429 时回本地 | 开启 | 外部账号限流时允许回本地。 |
| 超时时回本地 | 开启 | 外部账号超时时允许回本地。 |
| 容量失败回本地 | 开启 | 外部账号容量不足时允许回本地。 |
| 回本地最多等待 | 15 秒 | 回本地抢救最多等 15 秒。 |

### 八、外部池 -> 外部账号列表 -> 编辑外部账号 -> 调度设置

这是单个外部账号自己的设置，不是全局配置。

| 页面文案 | 推荐值 | 说明 |
|---|---|---|
| 单账号最大并发 | 按该外部账号真实能力设置 | 例如该外部账号稳定只能承接 20 并发，就填 20；不要盲目填很大。 |
| 启用外部账号 | 按需开启 | 确认该外部账号可用后再开启参与调度。 |

## 页面不可配置项

这些项页面上找不到，不要在后台页面里找。

### 一、独立观测 Redis

| 项目 | 状态 | 处理方式 |
|---|---|---|
| 独立观测 Redis 地址 | 页面不可配置 | 通过启动配置文件或环境变量配置。 |
| 独立观测 Redis 前缀 | 页面不可配置 | 通过启动配置文件或环境变量配置。 |

说明：

- 独立观测 Redis 用于 usage 派生、统计缓存、后台缓存和清理任务。
- 它不能和业务调度 Redis 共用同一个 Redis 服务进程。
- 只换逻辑库编号或前缀不算隔离。
- 如果未配置，观测路径会使用 PostgreSQL 或进程内状态，不会回落到业务调度 Redis。

### 二、调度 Redis 热路径保护

| 项目 | 状态 | 当前处理方式 |
|---|---|---|
| 调度 Redis 热路径超时 | 页面不可配置 | 代码内部固定保护。 |
| 调度 Redis 连续失败后打开保护状态 | 页面不可配置 | 代码内部固定保护。 |
| 调度 Redis 降级后 fallback 判断优先级 | 页面不可配置 | `v0.0.124` 已通过代码修复。 |

说明：

- 页面上能配置的是“调度 Redis 降级时使用外部账号”。
- 页面上不能配置热路径超时时间和连续失败次数。
- 本次发版已经修复“调度 Redis 已降级但本地还有可调度账号数量时外部账号 fallback 被压掉”的代码逻辑。

### 三、客户端重试策略

| 项目 | 状态 | 处理方式 |
|---|---|---|
| 客户端失败后重试间隔 | 服务端页面不可配置 | 在调用方、上游网关或客户端侧配置。 |
| 客户端最大重试次数 | 服务端页面不可配置 | 在调用方、上游网关或客户端侧配置。 |

建议：

| 项目 | 推荐值 |
|---|---:|
| 失败后最小重试间隔 | 3 到 5 秒 |
| 最大重试次数 | 2 到 3 次 |

不要让客户端按 1 秒或更短间隔持续重试，否则服务端已经限流时，入口压力仍会被持续喂满。

### 四、已经存在的数据库运行态配置

| 项目 | 状态 | 处理方式 |
|---|---|---|
| 已经保存到数据库里的运行态配置 | 不会被代码默认值自动覆盖 | 必须通过页面保存、运行态配置接口或数据库更新。 |
| 代码里的默认配置 | 只在新初始化或字段缺失时生效 | 升级版本不会强行改现网已有配置。 |

说明：

- 升级到 `v0.0.124` 后，新实例初始化会使用更稳的默认值。
- 如果现网数据库里已经有旧配置，比如 300 秒等待、100 队列、3000 全局并发，这些值仍然会继续生效，直到你在页面保存新的运行配置。

## 保存后验证

保存配置后，建议观察以下页面或现象：

| 观察项 | 期望 |
|---|---|
| 运行配置保存后新请求 | 立即使用新配置。 |
| 调度 Redis 降级时 | 外部账号 fallback 不再被本地可调度数量压掉。 |
| 本地排队请求数 | 不应长期贴近最大排队请求数。 |
| 入口 429 | 高峰时可能增加，但服务进程 CPU 不应被等待队列放大打满。 |
| 外部账号请求 | Redis 调度降级时可能增加，属于预期。 |
| GHCR 或部署版本 | 确认已使用 `v0.0.124` 或之后版本。 |
